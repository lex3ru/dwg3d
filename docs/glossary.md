# Глоссарий

Термины предметной области и внутренний жаргон проекта. Агенты используют их в коде, тестах и документах — пишите так, как принято у заказчика и в коде.

| Термин | Значение | В коде |
| --- | --- | --- |
| Проведение | Документ учёта из черновика становится действующим: меняет места, состояния и остатки. Целиком или никак (ТЗ 5.4.4 п. 3) | `inventory.documents.post` |
| Обратный документ | Отмена проведённого документа: новый документ сегодняшним числом со ссылкой на исходный. Отменённый и обратный взаимно гасятся | `cancel`, `Document.cancels_id` |
| Событие единицы | Что стало с инвентарной единицей после документа, объединения или уборки помещения: место, состояние, оценка — на дату. Из событий строятся отчёты «на дату» | `UnitEvent`, `units.events_at` |
| Задним числом | Документ с датой раньше сегодняшней. Не раньше проведённой инвентаризации мест (5.4.4 п. 2); по единице — не раньше её последнего события, по количеству — без минуса на любую дату (ADR-0004) | `Posting.not_before_last_event`, `Posting.available` |
| Очередь учёта | Номера и остатки меняет один сеанс за раз: создание, проведение и отмена документов ждут друг друга (ADR-0003) | `inventory.documents.lock` |
| Место учёта | Где числится единица или остаток: помещение, склад или ячейка склада. Хранится ключом `r:/w:/c:<uuid>`; вид ключа проверяет база, существование места — страница состояния (ADR-0009) | `inventory.places`, `rules.PLACE_KEY`, `places_check` |
| Убранное помещение | Помещение, которое ушло в архив при сохранении плана: в новом плане его не узнали по подписи. Его имущество переходит в помещение плана, выбранное администратором; ведомость этажа включает убранные помещения, где что-то числится (ADR-0008) | `building.save_plan(moves=…)`, `room_property`, `archived_rooms` |
| Позиция остатка | Остаток количественного учёта: место + тип + модель. «Без модели» — тоже позиция. Приход, расход, отчёт «Остатки» и пересчёт при инвентаризации — по позиции (ADR-0005) | `StockMove`, `CountStock`, `Posting._position` |
| Пересчёт | Фактическое количество позиции остатка, введённое при обходе. При проведении разница с учётом — строка «недостача» или «излишек» той же позиции | `counts.set_stock`, `post_count` |
| Лента журнала | Записи журнала по одной вещи или месту: зданию, этажу, помещению, предмету, единице, документу, пользователю (5.7.3). Запись попадает в ленту по ссылке вида `room:<id>`; ссылки на здание и этаж ставит модуль, который пишет запись (ADR-0013) | `journal.api.feed(ref=…)`, `Places.refs`, `web/src/lib/journal.ts` |
| Страж журнала | Проверка в тестах сервера: запрос, изменивший данные без записи журнала, валит тест (9.2 п. 3). Служебные таблицы — в перечне с причиной (ADR-0013) | `server/tests/conftest.py`, `NOT_DATA` |
| Очередь отметок | Метки, ручные отметки и пересчёт обхода, которые телефон ещё не отправил. Хранится в браузере, досылается сама; отметка уходит из неё, только когда сервер её принял или отказал по ней самой (6.7 п. 1). Запрос без ответа 15 с обрывается и повторяется | `web/src/inventory/queue.ts` |
| Номер отметки | Порядковый номер, который отметка получает от устройства (браузера) при постановке в очередь; повторы идут с тем же номером. Сервер пропускает запрос с номером не больше последнего принятого от этого устройства в ведомости — опоздавший старый запрос не меняет ни отметку, ни пересчёт (ADR-0006) | `queue.ts` (`headersOf`), `counts._fresh`, `inventory.count_device` |
| Режим проекта | Редактор правит проект, а не расстановку: фиолетовые полоса и рамка, «Строительства», «+ этаж» и учёта нет. Режим живёт в адресе (`?project=<id>`): смена этажа, вид и 3D его сохраняют, выйти — только явно («Как есть»); проект не открылся — так и сказано, расстановка вместо него не открывается (5.3.6 п. 2, 6.5.2) | `?project=`, `editor/floors.ts` (`floorUrl`, `projectFloor`) |
| Фоновая задача | Длительная операция вне запроса: разбор и перевод чертежа, полная выгрузка, загрузка здания. Идёт в своём процессе, с ходом, сроком и «Отменить»; не выполнена — модуль узнаёт об этом и возвращает свои записи (ADR-0011) | `core.tasks`, `@task(timeout, lane, on_fail)` |
| Полоса очереди | Очередь фоновых задач делится на полосы: «чертежи» и всё остальное. В каждой — одна задача, полосы идут одновременно, поэтому тяжёлый чертёж не держит выгрузки (ADR-0011) | `tasks.LANES`, `lane=` |
| Очередь запросов | Не путать с очередью задач и очередью учёта: процесс приложения обслуживает одновременно до `APP_DB_POOL` HTTP-запросов, остальные ждут в нём, не занимая ни потока, ни соединения с базой (ADR-0020) | `core/admission.py`, `Admission` |
| Лимит загрузки | Наибольший размер файла своего вида (ТЗ 7.3 п. 4); задаётся в «Настройках», проверяется до приёма файла и после проверки входа (ADR-0012) | `system.upload_limit`, `uploads.receive` |
| Адрес меток | Постоянный адрес системы в ссылке QR-метки (ТЗ 5.4.7): настройка «Адрес системы для QR-меток», пусто — `PUBLIC_URL` установки, без него — адрес, по которому открыли систему. Печать не с этого адреса — предупреждение (ADR-0016) | `inventory.api.label_base`, заголовок `X-Label-Url` |
| Версия установки | Тег `vX.Y.Z` кода, который поставил последний удачный `install.sh`. X — обновление требует действий администратора, Y — новые возможности и переносы данных, Z — исправления без миграций; между тегами — `тег-N-gхеш` (ADR-0023) | `deploy/install.sh`, `deploy/.version` |
| Копия перед обновлением | Резервная копия, которую `install.sh` делает до сборки новой версии и путь которой печатает. Откат неудачного обновления — прежний тег и `restore.sh` с этой копией: копия восстанавливается в отдельную базу и подменяет текущую, прежняя удаляется после удачного запуска (ADR-0023) | `install.sh` (`copy`), `deploy/restore.sh`, `deploy/backup/restore-db.sh` |
| Масштаб листа | Во сколько раз здание больше чертежа: план в миллиметрах бумаги 1:500 — 500. Берётся из множителя размеров `DIMLFAC` большинства размеров (если чертёж в мм и размером с лист) или задаётся администратором в карточке чертежа — тогда чертёж разбирается заново; части и планы — в мм здания (ADR-0025) | `read.load(scale)`, `Drawing.scale`, `drawing.sheet` |
| Роль слоя | Что значит слой чертежа — по началу слов его названия: стены, перегородки, окна, двери, колонны, лестницы, лифты, заливки, «прочее» (в том числе «0») или «не нужен» (оси, размеры, текст, мебель). Если на слоях стен почти ничего нет, стены берутся и с «прочих» | `layers.role`, `convert._has_walls` |
