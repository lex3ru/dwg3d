# Этап 10. Установка и эксплуатация

`deploy/` (Dockerfile, compose, Caddy, `install.sh`, `restore.sh`, копии), `.gitlab-ci.yml`,
`docs/INSTALL.md`. Образ собран из копии `HEAD` (этап 0), копия и восстановление проверены
делом (этап 9).

## Итог

Установка продумана: одна команда, копия перед обновлением, приложение без прав root, наружу —
только Caddy, секреты в `.env` с правами `600`. Находки — эксплуатационные: красный CI (R-005,
этап 0), открытая загрузка без лимита (R-014, этап 2), права и размещение копий (R-035,
этап 9), не описан откат неудачного обновления (R-037), гигиена сборки и журналов (R-038,
R-039).

## Что проверено

| Тема | Вывод |
|---|---|
| Образ | Многоступенчатая сборка; в образе — сервер, собранный интерфейс, LibreDWG 0.14; без тестов и прежних версий; пользователь `app` (uid 10001); `HEALTHCHECK` по `/api/health`. LibreDWG — без контрольной суммы, базовые образы — по тегам (R-038) |
| `.dockerignore` | Пропускает только `server/` и `web/`, без `.venv`, `node_modules`, тестов; не исключает `server/.dev-data`, `.volume-data` (R-038) |
| compose | Порядок запуска по здоровью (база → приложение → обработчик, Caddy); `restart: unless-stopped`; тома для базы, файлов, Caddy; наружу — только 80/443; у обработчика проверка здоровья отключена правильно; нет ротации журналов (R-039) и лимитов памяти |
| `install.sh` | `set -euo pipefail`; первая установка — `.env` с паролем базы (`chmod 600`), администратор с временным паролем; повторный запуск — копия, при её неудаче обновление отменяется; по умолчанию копии — в `deploy/backups` без предупреждения (R-035) |
| `restore.sh` | Переспрашивает «да»; останавливает приложение, обработчик, Caddy; `pg_restore --clean --if-exists`; файлы — заменой; запуск — проверено (этап 9) |
| Обновление | `git pull && install.sh`; миграции — при старте под блокировкой; откат при неудаче не описан (R-037) |
| Caddy | HTTPS (свой центр сертификации или Let's Encrypt), `http` → фиксированный адрес, HSTS, `nosniff`, `X-Frame-Options DENY`; нет CSP (R-018) и лимита тела запроса (R-014) |
| CI | Те же проверки, что локально (`ruff`, `pytest`, `tsc`, `oxlint`, сборка, e2e); красный (R-005, R-007, R-008); предупреждения линтера не валят; uv — `curl \| sh` (R-038) |
| Журналы | Ошибка у пользователя — с кодом, по нему находится стектрейс (`INSTALL.md`, этап 1); строк доступа ≈ 100 байт на запрос, без ротации (R-039) |

## Не проверено

- `install.sh` на чистом Linux-сервере — машина ревью на Windows; стенд `planuchet` поставлен
  разработчиком тем же скриптом (19.10), он работает.
- Let's Encrypt (`CADDY_TLS` = почта) — нужен внешний адрес.
