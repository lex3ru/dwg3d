# План ревью

Коммит `e43c6a9` (все этапы «сделан, ждёт приёмки»). Цель — дефекты до приёмки: логика,
доступ, расхождения с ТЗ, эксплуатация; каждый — воспроизводимо.

## Правила

- **Код не исправляется по ходу ревью.** Находка записывается в [FINDINGS.md](FINDINGS.md);
  исправления — отдельно, по решению владельца.
- **Стенд `planuchet-*` (docker compose из `deploy/`) не трогаем** — ни данных, ни
  контейнеров. Для тестов поднимается отдельная база разработки (README, порт 55432), тесты
  создают в ней свою `app_test`.
- `legacy/`, `legacy2/` — вне объёма (ТЗ 9.1). Проверяется только, что они не попадают в
  образ и не импортируются.
- Каждая находка — с `файл:строка`, сценарием «что сделать → что получится» и, где можно,
  подтверждением (тест, запрос, вывод команды). Неподтверждённое помечается «предположение».

## Шкала важности

| Уровень | Что значит |
|---|---|
| **Б — блокер** | потеря или порча данных, обход доступа, падение на штатном сценарии; приёмка невозможна |
| **К — критично** | неверный результат в учёте (количества, суммы, остатки), нарушение требования ТЗ, уязвимость с условиями |
| **З — значимо** | ошибка на нештатном пути, заметная деградация, недостающая проверка или тест на важное |
| **Н — незначительно** | неудобство, неточность в документации, мелкая неэффективность |
| **С — совет** | стиль, упрощение, на будущее |

## Этапы

Порядок: базовая линия и ядро → безопасность и учёт (самое рискованное) → остальные модули
→ сквозные темы → сверка с ТЗ. Каждый этап — свой файл заметок и записи в FINDINGS.md.
Ручной прогон ([MANUAL-RUN.md](MANUAL-RUN.md)) идёт независимо от этапов; его отчёт —
вход для этапа 12.
