# Этап 8. Тесты

Сервер — `server/tests` (100 тестов), интерфейс — e2e Playwright (46), модульных тестов
интерфейса нет (R-003). Статистика — `artifacts/stage8-test-stats.txt`.

## Итог

Тесты сильные там, где их писали: сценарии ТЗ, права доступа, атомарность. Но **все четыре
критичных дефекта и почти все значимые лежат в местах, где тестов нет** (R-033):
одновременность, документы задним числом, остатки с моделями, обработчик фоновых задач
отдельным процессом. Набор зелёный только при условиях, которых нет в CI (R-005, R-007,
R-008).

## Что проверено

| Тема | Вывод |
|---|---|
| Объём и глубина | 99 функций (+1 параметризованная), 547 проверок — 5,5 на тест; 21 % проверок — только код ответа; 79 отрицательных проверок; медиана 15 строк, крупнейший сценарий — 135 строк (С18) |
| Покрытие | 82 % строк и ветвей (этап 0); слабее всего — перевод чертежей (57 %, тесты на чертежах заказчика пропущены), места хранения (57 %) |
| Пробелы против дефектов | Таблица в R-033 |
| Изоляция | Фикстура `clean` очищает таблицы после каждого теста; база тестов — своя (`app_test`), пересоздаётся `DROP … WITH (FORCE)` — два прогона на одном сервере базы мешают друг другу |
| Атомарность (`test_reliability.py`) | Исключение подставляется в конец операции — проверено честно; обрыв процесса и расхождение файлов с базой не проверяются |
| Права (`test_security.py`) | ~40 адресов чтения у «просмотра»; изменения, сортировка, гость — не проверяются (закрыто зондами этапа 2) |

| Архитектура (`test_architecture.py`) | Ловит 1 из 5 видов нарушений (R-010) |
| e2e: сценарии | Все С1–С22 есть (`stage1…stage10.spec.ts`); при текущем коде падают 4 из 46 — 1 настоящий дефект (R-007), 3 — сами тесты (R-008) |
| e2e: нестабильность | Ожиданий по таймеру — 6: по 300 мс «дождаться отрисовки» после появления плана (`stage6`, `stage8`, `a11y`) — возможный источник случайных падений на медленной машине; опрос задачи (`volume`), замеры (`perf`). Остальное — ожидание состояний. Сервер: `test_events` зависит от времени (R-034) |
