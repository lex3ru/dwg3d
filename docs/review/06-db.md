# Этап 6. База и миграции

12 миграций (`server/migrations/versions`), `env.py`, `test_migrations.py`, индексы по всем
схемам (`artifacts/stage6-indexes.txt`), триггер журнала.

## Итог

База в порядке: миграции проходят вверх и вниз, модели совпадают с миграциями, индексы
покрывают горячие запросы, журнал защищён от правки в самой базе. Одна находка уровня
«совет» — R-028 (нет `CHECK` и внешних ключей там, где целостность держит только код).

## Что проверено

| Тема | Вывод |
|---|---|
| Цепочка | Линейная 0001 → 0012, версия — в `core.alembic_version`; миграции под `pg_advisory_lock` (приложение и обработчик не мигрируют одновременно) |
| Откаты | «Лесенка» в образе CI на отдельной базе: каждая ревизия — вверх, на шаг вниз, снова вверх; затем `base ↔ head` — всё прошло (`artifacts/stage6-migrations.log`) |
| Модели ↔ миграции | `test_migrations.py` (autogenerate-сравнение) проходит; не сравнивает значения по умолчанию, `CHECK`, триггеры |
| Миграции данных | Только создание и удаление схем, функции и триггеров журнала; переноса данных нет — все миграции написаны 16.10, установок со старыми схемами нет |
| Индексы | GIN по `journal.entry.refs`; у движений остатков — по месту, типу, дате, документу; у событий единиц — по единице, документу, дате; уникальность `item.unit_id`, номеров, кодов меток. Составных индексов под `DISTINCT ON (unit_id) … date, seq` и остаток «место + тип + модель» нет — на объёмах 8.1 разработчик намерил нормы (проверка — этап 9) |
| Схема на модуль | Внешние ключи — только вниз по уровням (тест архитектуры); ссылки между модулями одного уровня — без ключей |
| Журнал | Триггеры `append_only` и `append_only_truncate`: `UPDATE`, `DELETE`, `TRUNCATE` → «журнал только для добавления» (проверено); удаление — только с `SET LOCAL journal.purge='on'` (очистка по сроку). Владелец базы может снять триггер — это защита от ошибок, а не от злоумышленника |
| Ограничения | Нет `CHECK` на состояние, вид, статус, знак количества; место — строка без ключа (R-028) |

## Замечание об окружении

На Windows `alembic downgrade -1` в цепочке команд Git Bash повис без соединения с базой и
без нагрузки; в образе CI та же последовательность прошла. Это особенность запуска на
Windows, к миграциям не относится.
