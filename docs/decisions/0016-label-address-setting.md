# 0016. Адрес в QR-метках — из «Настроек», по умолчанию PUBLIC_URL установки

- Статус: предложено
- Дата: 2026-10-29
- Задача: DWG3D-16 · MR: !16
- Участники: Yury Mikhailov; готовил: Claude Code / claude-opus-5-5

## Контекст

Ссылка в QR-метке постоянная (ТЗ 5.4.7): наклейку один раз клеят на монитор, и через годы она
должна открывать карточку с телефона. Адрес в метку подставлял браузер печатающего
(`origin: window.location.origin` в `POST /api/inventory/labels.pdf`), метки мест из отчётов —
`request.base_url`. Администратор, открывший систему на самом сервере по `https://localhost`
или по другому имени, печатал наклейки, которые камера телефона не откроет (R-016). Постоянный
адрес у установки уже есть: `PUBLIC_URL` в `deploy/.env` пишет `install.sh`, на него Caddy
перенаправляет с `http://`. Но приложению он не передавался.

## Рассмотренные варианты

1. **Только `PUBLIC_URL` установки** (`APP_PUBLIC_URL`). Плюсы: один источник адреса, как у
   Caddy; ничего в интерфейсе. Минусы: сменить адрес меток можно только правкой `.env` и
   перезапуском; при установке по `localhost` метки сломаны, пока не переустановят.
2. **Поле в «Настройках», пусто — `PUBLIC_URL`, без него — адрес запроса.** Плюсы:
   администратор видит и меняет адрес без перезапуска; по умолчанию — адрес установки, при
   разработке работает как раньше. Минусы: адрес меток может разойтись с адресом установки —
   поэтому в «Настройках» видно, куда метки ведут сейчас и откуда этот адрес.
3. **Как было, адрес от браузера, с предупреждением.** Плюсы: без новых настроек. Минусы:
   ссылка в метке по-прежнему зависит от того, кто и откуда печатает, — требование 5.4.7 не
   выполнено.

## Решение

Вариант 2, выбрал пользователь: адрес меняют без перезапуска, а по умолчанию он совпадает с
адресом установки. Порядок — `api.label_base()` модуля учёта: настройка `label_url` →
`APP_PUBLIC_URL` → адрес запроса. Им печатаются метки единиц, складов, ячеек и мест.

Публичный API:

- `POST /api/inventory/labels.pdf` больше не читает `origin` (старый клиент, приславший его,
  не ломается — поле пропускается) и отдаёт использованный адрес в заголовке `X-Label-Url`;
- новый `GET /api/inventory/labels/address` → `{url, source}`, `source` — `settings`,
  `install` или `request`;
- настройка `label_url` в `/api/system/settings`: `http(s)://имя[:порт]` без пути, пусто —
  по умолчанию.

## Последствия

- `deploy/compose.yml` передаёт `PUBLIC_URL` приложению как `APP_PUBLIC_URL`; на работающей
  установке он появится после `install.sh` или `docker compose up -d`.
- Интерфейс предупреждает, если система открыта не по адресу меток (после печати и в
  «Настройках»), если адрес — `localhost` и если ни настройки, ни адреса установки нет.
- Напечатанные раньше наклейки с неверным адресом настройка не исправит — их перепечатывают.
  Встроенный сканер приложения читает код из пути и открывает и такие.
- Пересмотреть, если система будет открываться по нескольким равноправным адресам (например,
  изнутри сети и снаружи): тогда метке нужен адрес, который работает из обеих сетей.
