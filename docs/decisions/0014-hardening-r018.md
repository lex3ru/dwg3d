# 0014. Файл по ключу проверяет модуль-владелец; схема API — администратору; CSP ставит приложение; данные в браузере — по пользователю

- Статус: предложено
- Дата: 2026-10-28
- Задача: DWG3D-14 · MR: !14
- Участники: Yury Mikhailov; готовил: Claude Code / claude-opus-5-5

## Контекст

Ревью 21.10.2026 (R-018, «совет») нашло в укреплении шесть пробелов. Четыре из них меняют
поведение публичного API или устройство приложения.

- **Файлы.** `GET /api/files/{id}` отдавал вошедшему любой файл. Защитой была только
  неугадываемость UUID. Права проверялись лишь у гостя по ссылке, и только через подписку
  `files.on_guest_file`. Модуль файлов — нижний уровень: он не знает, чей это файл.
- **Схема API.** `/api/docs` и `/api/openapi.json` (120 адресов) открывались без входа.
- **CSP** не было. Встроенных скриптов в коде нет, кроме скрипта темы в `index.html`.
  pdf.js грузит воркер, а 3D-модели декодируются в WebAssembly (meshopt у `useGLTF`).
  Метки печатаются как PDF из `blob:` в новой вкладке. e2e в CI идёт на `uvicorn` мимо Caddy.
- **`localStorage`.** Черновик плана, очередь отметок инвентаризации и список фоновых задач
  общие для браузера. На общем компьютере другой вошедший видит чужой черновик и дошлёт чужие
  отметки от своего имени.

## Рассмотренные варианты

**Файлы**

1. **Проверку делает модуль-владелец.** `files.on_file_access(check)` вместо `on_guest_file`;
   администратору можно всё, остальным — если какой-то check подтвердит.
   Плюсы: тот же механизм, что у гостя; уровни модулей не нарушены. Минусы: на каждый файл
   «просмотра» — запросы к модулям-владельцам.
2. **Владелец в записи файла** (`owner_kind`, `owner_id`). Плюсы: один запрос. Минусы:
   миграция и заполнение старых записей. Файл бывает у нескольких владельцев: модель каталога
   у нескольких типов, фото из пакета переноса. Модуль файлов всё равно не знает, кому что
   видно.
3. **Подписанные ссылки с истечением.** Плюсы: без запросов при выдаче. Минусы: все ответы с
   `/api/files/…` меняются, ссылки в кэше браузера и в 3D протухают.

**Схема API:** только администратору / выключить совсем (или включать настройкой) /
оставить открытой.

**CSP:** в приложении на ответе `index.html` / в Caddyfile рядом с другими заголовками.

**`localStorage`:** ключ с id пользователя / ключ с id и очистка при выходе / оставить.

## Решение

- **Файлы — вариант 1.** Здание отвечает за подложки (их видит и гость) и исходные чертежи.
  Учёт отвечает за фото и документы видимых единиц: и по `unit_file`, и по `photo_file_id`,
  потому что фото из пакета переноса бывает без строки `unit_file`. Каталог отвечает за модели,
  они открыты всем. Файлы документов учёта и инвентаризации «просмотру» закрыты: у него нет
  этих разделов.
- **Схема API — только администратору.** Выключать не стали: схема нужна при отладке и
  интеграции. У страницы Swagger своя политика `DOCS_CSP`: он грузит скрипт с CDN и
  запускается встроенным скриптом.
- **CSP ставит приложение** (`WEB_CSP` в `main.py`, только на `index.html`): так e2e видит её
  в CI. Скрипты — только `'self'`, без встроенных и `eval`. Скрипт темы вынесен в `theme.js`.
  `'wasm-unsafe-eval'` нужен для декодера meshopt. `object-src blob:` — для PDF меток: вкладка
  `blob:` наследует политику, и PDF в ней — «объект». Стили — с `'unsafe-inline'`: их ставят
  библиотеки окон и 3D. Все e2e-сценарии идут через `e2e/tests/fixtures.ts`: сценарий падает,
  если браузер что-то заблокировал по CSP.
- **`localStorage` — ключ с id пользователя** (`web/src/lib/userStorage.ts`), без очистки при
  выходе. Неотправленные отметки и несохранённый план не должны пропадать из-за выхода, а
  другой вошедший их и так не увидит. Данные прежней версии без пользователя достаются первому
  вошедшему. Настройки вида (тема, слои, столбцы реестра) остаются общими для устройства.

## Последствия

- Новый вид файла, который должен видеть «просмотр» или гость, требует своего
  `on_file_access` в модуле-владельце. Иначе файл получит только администратор. Это видно
  сразу: на экране «просмотра» не загрузится картинка.
- CSP не пускает внешние адреса. Draco-сжатая 3D-модель, для которой `useGLTF` брал декодер
  с gstatic.com, не загружалась (в закрытой сети — и раньше). DWG3D-15: модели грузит
  `GLTFLoader` из three, а декодер Draco берётся из поставки three и лежит в сборке, в
  `assets/` (`web/src/catalog/gltf.ts`, ADR-0015). Политику менять не пришлось: декодеру хватает
  `'self'`, `blob:` для воркера и `'wasm-unsafe-eval'`.
- В Caddyfile CSP нет. При установке за другим прокси политика всё равно приходит от
  приложения.
- Данные в браузере после выхода остаются. Их видно через инструменты разработчика под учётной
  записью Windows. В них нет стоимости, только план и отметки.
