# 0005. Инвентаризация пересчитывает остаток по позиции «место + тип + модель»

- Статус: предложено
- Дата: 2026-10-26
- Задача: DWG3D-4 · MR: !4
- Участники: Yury Mikhailov; готовил: Claude Code / claude-opus-5-5

## Контекст

Остаток количественного учёта хранится по позиции «место + тип + модель»
(`inventory.stock_move.model_id`). По позиции работают приход, расход и отчёт «Остатки».
Инвентаризация (5.4.6 п. 3, С18) была единственным местом, где остаток считался по месту и
типу:

- в ведомости показывалась сумма всех моделей типа;
- пересчёт (`inventory.count_stock`) хранился без модели;
- строки «недостача» и «излишек» при проведении тоже шли без модели.

Недостача списывалась с позиции без модели, а у остатка с моделью такой позиции нет. Система
отвечала «… — 0, нужно 1», и не проводилась вся ведомость. Излишек ложился новой позицией без
модели (R-021). В образце `docs/samples/имущество-пример.xlsx` модель есть у 5 из 8
количественных типов, поэтому С18 с пересчётом остатков на нём не проходила.

## Рассмотренные варианты

1. **Пересчёт по позиции «место + тип + модель».**
   - Плюсы: ведомость совпадает с отчётом «Остатки» и с тем, как остаток списывается. Комиссия
     считает каждую модель отдельно («Бахилы 100 пар», «Перчатки размер M»). Расхождение
     однозначно ложится на свою позицию по её цене.
   - Минусы: меняются схема `count_stock` и API `PUT /api/inventory/counts/{id}/stock` (поле
     `model_id`). Пересчёт, уже введённый в черновики, надо перенести. В ведомости больше строк.
2. **Пересчёт по месту и типу, расхождение распределяется по моделям.**
   - Плюсы: схема и API не меняются.
   - Минусы: с какой модели списывать недостачу, решает выдуманное правило (пропорционально,
     с наибольшего остатка, по очереди). Акт расхождений говорит не то, что нашла комиссия.
     Излишек не к чему привязать. У моделей разные цены, поэтому стоимость недостачи зависит от
     правила, а не от того, чего не хватает.
3. **Количественный учёт без моделей.**
   - Минусы: модели есть в каталоге и в образце (размер перчаток, фасовка бахил), и их пришлось
     бы выбросить. Отвергнут сразу.

## Решение

Вариант 1, выбран вместе с Yury Mikhailov. Главная причина: инвентаризация считает то же, что
хранит учёт, — позицию. Иначе расхождение приходится угадывать.

Как устроено (`server/app/modules/inventory/counts.py`):

- `inventory.count_stock`: ключ — суррогатный `id`, позиция уникальна (документ, место, тип,
  модель) с `NULLS NOT DISTINCT` (PostgreSQL 15+). Позиция «без модели» тоже одна, и пересчёт
  у неё один.
- `PUT /api/inventory/counts/{id}/stock` принимает `model_id`: пусто — позиция без модели.
  Модель другого типа — ошибка 400.
- Ведомость (`GET /api/inventory/counts/{id}?place=…`) — строка на позицию: `type_id`,
  `model_id`, `title` (тип и модель), по учёту и фактически. В PDF ведомости и в акте
  расхождений — тоже с моделью.
- При проведении строки «недостача» и «излишек» получают `model_id` позиции. Списание и
  приход — как в любом документе (`Posting.take`, `Posting.stock`).
- Миграция `0013` переносит пересчёт в черновиках ведомостей. Если у типа в этом месте одна
  позиция с остатком (с моделью или без), пересчёт получает её модель. Если позиций несколько,
  пересчёт этой строки удаляется: его вводят заново, по моделям. Если позиций нет, пересчёт
  остаётся без модели. В проведённых и отменённых ведомостях пересчёт не трогается: их итог
  записан в строках документа.

## Последствия

- Клиент при пересчёте шлёт `model_id`. Клиент без этого поля пересчитывает позицию без
  модели, и при остатке с моделью расхождение ляжет не туда. Интерфейс и e2e обновляются в том
  же MR.
- На стенде, где при обновлении есть начатые ведомости с пересчётом по типу с несколькими
  моделями, этот пересчёт придётся ввести заново. Об этом сказано в описании MR.
- PDF ведомости, проведённой до обновления, показывает пересчёт только у позиций без модели:
  расхождения в акте при этом верные, они берутся из строк документа.
- Постановка на учёт с плана (`link`) по-прежнему считает количество по типу, без модели.
  R-021 этого не касается. Если на плане появятся модели количественных предметов, это стоит
  пересмотреть тем же способом.
