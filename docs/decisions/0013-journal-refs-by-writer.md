# 0013. Ссылки на здание и этаж ставит модуль, который пишет запись журнала; страж журнала в тестах

- Статус: предложено
- Дата: 2026-10-28
- Задача: DWG3D-13 · MR: !13
- Участники: Yury Mikhailov; готовил: Claude Code / claude-opus-5-5

## Контекст

- **R-011.** Не каждое изменение данных пишет журнал (9.2 п. 3): черновики документов учёта,
  правка проекта, перенос имущества при объединении помещений. Найдено скриптом ревью,
  а не тестом — следующий пропуск тоже найдут не сразу.
- **R-041, R-012.** Записи находятся по ссылкам `refs` вида `room:<id>`. Ленты здания и этажа
  (5.7.3) и события «просмотру» (6.1 п. 8) отбираются по `building:`/`floor:`. Записи учёта
  этих ссылок не несут: ленты здания и этажа их не видят, «просмотру» не приходят изменения
  учёта.
- **Уровни модулей (9.2).** Журнал — нижний уровень. Он не знает, в каком здании помещение,
  склад или единица.
- **Сокет `/api/ws`** проверяет сеанс один раз при подключении. Заблокированный пользователь
  получает события, пока соединение не оборвётся.

## Рассмотренные варианты

1. **Ссылки ставит модуль, который пишет запись** — так уже делают `building` и `planning`.
   Учёт берёт здание и этаж из мест (`Places.refs`).
   - Плюсы: без нового механизма. Всё в той же транзакции, ссылки — из данных, которые модуль
     уже загрузил.
   - Минусы: каждый модуль должен помнить про ссылки. Старые записи без них.
2. **Журнал вычисляет ссылки сам при записи** — через подписчиков, которых регистрируют
   модули выше (как `on_rooms_continued`).
   - Плюсы: правило соблюдается само.
   - Минусы: лишний запрос на каждую запись. Неявная связь «журнал зовёт модули выше».
     Модули всё равно должны дать сущности, по которым вычислять.
3. **Лента вычисляет ссылки при чтении** — все помещения, единицы и документы здания, затем
   пересечение массивов (как полная выгрузка, `entries_for`).
   - Плюсы: в ленте и старые записи.
   - Минусы: маршрут журнала зависит от модулей выше. С постраничной лентой и фильтрами
     запрос по тысячам ссылок тяжелеет. R-012 не решает: событию «просмотру» ссылка на
     здание нужна в момент записи.

Как не пропустить изменение без записи: тест на каждую функцию; скрипт по исходнику, как у
ревью; проверка во время тестов — на сессиях запросов.

## Решение

Вариант 1. Только он решает и ленты, и события «просмотра» без зависимости журнала от модулей
выше.

- **Ссылки в событии.** У события канала не больше 40 ссылок. Ссылки на здание и этаж идут
  сразу за сущностью — обрезка их не уберёт.
- **Старые записи** ссылками не дописываются: журнал не правится (5.7.3).
- **Страж журнала** — в `server/tests/conftest.py`. События SQLAlchemy собирают таблицы,
  изменённые в транзакции запроса. Транзакция зафиксирована без записи журнала — тест падает.
  Служебные таблицы — в `NOT_DATA` с причиной. Страж ходит по всем тестам сервера, поэтому
  ловит и то, о чём не подумали: так нашёлся запуск перевода чертежа.
- **Сокет** перепроверяет сеанс раз в 25 с (`RECHECK_AFTER`). Ещё он перепроверяет его сразу,
  когда пришло событие о самой учётной записи: блокировка, смена зданий, сброс пароля. Если
  сеанс недействителен, сокет закрывается кодом 4401. Перепроверка на каждое событие отвергнута:
  это запрос к базе на каждое изменение для каждого открытого сокета.

## Последствия

- **Новый модуль, который пишет журнал** о вещах здания, сам передаёт `building:` и, где есть,
  `floor:`. Страж проверяет, что запись есть, но не что в ней есть ссылки. Ссылки проверяют
  тесты лент (`test_journal.py::test_r041_*`).
- **Сырой SQL** (`text(...)`) страж не видит.
- **Действие, которое тут же проводит документ** (Excel, перенос, отмена, инвентаризация),
  составляет черновик без записи (`new_draft`). Запись о проведении уже есть, и одно действие
  не даёт три записи.
- **Выход (`logout`)** журнал не пишет. Сокеты других вкладок закроются по таймеру — не позже
  чем через 25 с.
- **События `project.*`** «просмотру» не уходят: проектов он не видит (2.2).
- **Когда пересмотреть:** если ленты понадобятся и для записей до DWG3D-13. Тогда — вариант 3
  только для них, отдельной выборкой.
