# 0018. Сортировка реестра по месту — в базе: модуль здания отдаёт подзапрос подписей помещений

- Статус: предложено
- Дата: 2026-10-29
- Задача: DWG3D-17 · MR: !17
- Участники: Yury Mikhailov; готовил: Claude Code / Claude Opus 5.5

## Контекст

Реестр по месту сортируется по подписи места: «этаж › номер название» у помещения,
«Склад «…»» и «Склад «…» › ячейка». Подпись помещения — данные модуля здания, а учёт (уровнем
выше) обращается к нему только через `building.api` (9.2). После переноса сортировки в базу
(R-036) подписи всё ещё собирал Python: 8 000 мест стенда 8.1 — 0,15 с на каждый запрос, и
при 20 одновременных пользователях реестр по месту отвечал 2,2 с при норме 1 с (ТЗ 8.2).

## Рассмотренные варианты

1. **Подписи в базе: `building.api` отдаёт подзапрос подписей помещений**, учёт присоединяет
   его к единицам вместе со своими складами и ячейками и сортирует целиком в SQL — плюсы: в
   Python ничего не читается, запрос стоит десятки миллисекунд; минусы: формула подписи живёт
   дважды (Python и SQL), учёт соединяет чужой подзапрос — по правилам, но впервые.
2. **Кэш подписей мест в процессе на короткое время** — плюсы: формула одна, проще; минусы:
   после переименования помещения или этажа порядок ненадолго устаревает, а кэш в каждом из
   процессов приложения сбрасывается порознь.
3. **Не мерить сортировку по месту нормой 8.2** — плюсы: ничего не делать; минусы: это
   действие реестра (5.4.8), и на объёмах 8.1 оно заметно медленнее остальных.

## Решение

Вариант 1, выбран с пользователем. `building.room_title_sql` — та же формула, что
`room_title`, рядом с ней; `building.room_titles()` — подзапрос (id, building_id,
floor_name, title) без проверки прав: видимость зданий проверяет присоединяющий модуль.
`places.title_sql` в учёте — подпись места как у `Places.get`, с той же видимостью для
«просмотра» («место недоступно»).

## Последствия

- Модуль может отдавать модулям выше подзапрос своих таблиц через `api` — так же, как
  функции; соединять чужие таблицы напрямую по-прежнему нельзя (`test_architecture.py`).
- Подписи меняют в двух местах рядом. Расхождение ловят `tests/test_registry.py`: подпись
  помещения в базе и в Python на краевых номерах и названиях, подпись места каждой единицы в
  базе и в карточке — у администратора и «просмотра».
- Если подпись места усложнится (адрес здания, ветви для новых видов мест), Python- и
  SQL-версии придётся менять вместе; при заметном усложнении — пересмотреть в пользу кэша.
