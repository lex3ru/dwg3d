# Установка и обслуживание

Инструкция для администратора сервера (ТЗ 8.5, 8.7 п. 3). Система ставится на один
сервер в учреждении и работает в его локальной сети.

## Что нужно

- Linux-сервер (Ubuntu 22.04+, Debian 12+ или похожий): 4 ядра, 16 ГБ памяти, SSD 1 ТБ под
  данные и **отдельный диск** (или сетевое хранилище) под резервные копии (9.5).
- Docker Engine 24+ с Docker Compose v2 (команда `docker compose`), bash.
- Доступ в интернет — только на время установки и обновления (скачать образы и
  библиотеки). Работает система без него.
- Свободные порты 80 и 443 (или другие — см. ниже).

## Установка

```bash
git clone <адрес репозитория> planuchet && cd planuchet
./deploy/install.sh
```

Скрипт определит адрес сервера, создаст `deploy/.env` (пароль базы, адрес, порты, каталог
копий), соберёт и запустит систему, сделает первую резервную копию и заведёт администратора
`admin`. В конце он печатает адрес системы и **временный пароль** администратора; при первом
входе система попросит придумать свой.

Адрес можно задать явно (IP или имя, под которым сервер известен в сети):
`./deploy/install.sh 192.168.1.10`. Порты и каталог копий при первой установке — переменными:

```bash
HTTP_PORT=8080 HTTPS_PORT=8443 BACKUP_DIR=/mnt/backup/planuchet ./deploy/install.sh
```

Позже настройки меняются в `deploy/.env`; после правки снова запустите `install.sh`.

## Сертификат (HTTPS)

Система работает только по HTTPS (8.4 п. 1).

- **В локальной сети** (`CADDY_TLS=internal`, по умолчанию) сертификат выпускает сама
  система. Браузер предупредит о нём, пока на устройство не поставлен корневой сертификат
  системы. Скачайте его по адресу `http://<сервер>/ca.crt` и установите как доверенный:
  в Windows — двойной щелчок → «Установить» → «Доверенные корневые центры»; на iPhone —
  открыть файл, затем «Настройки › Основные › Об этом устройстве › Доверие сертификатам»;
  на Android — «Настройки › Безопасность › Установить сертификат».
- **Доступ извне** (8.5 п. 3): серверу нужно имя в интернете и открытые наружу порты 80 и
  443. В `deploy/.env`: `SITE_ADDRESS=имя.учреждения.ru`, `PUBLIC_URL=https://имя.учреждения.ru`,
  `CADDY_TLS=адрес@почты` — сертификат Let's Encrypt выпустится и будет обновляться сам.

## Размер загрузок

Наибольший размер файла по видам (ТЗ 7.3 п. 4) меняется в интерфейсе: «Настройки» →
«Загрузка файлов». Сервер проверяет вход и лимит до приёма файла (ADR-0012). Caddy
дополнительно не пропускает тело запроса больше 301 МиБ — это общий предел файла (300 МБ)
с запасом на форму. Пакету переноса здания Caddy разрешает до 10 241 МиБ. Если перед
системой стоит свой прокси, его лимит тела запроса должен быть не меньше этих чисел.

## Обновление

```bash
git pull && ./deploy/install.sh
```

Перед обновлением делается резервная копия; если она не удалась, обновление не
начинается. Данные переносятся сами (8.3 п. 5).

## Резервные копии

- Делаются каждую ночь (`BACKUP_AT`, по умолчанию в 02:00) в каталог `BACKUP_DIR`:
  `daily/<дата>` — база (`db.dump`) и файлы (`files/`); первая копия месяца остаётся в
  `monthly/<год-месяц>`. Хранятся 30 ежедневных и 12 ежемесячных копий (`KEEP_DAILY`,
  `KEEP_MONTHLY`). Файлы, которые не менялись, в копиях — жёсткие ссылки и места заново не
  занимают.
- **`BACKUP_DIR` должен быть на другом диске**, чем Docker (`/var/lib/docker`), — иначе
  копия погибнет вместе с данными (8.3 п. 3).
- Копия сейчас: `./deploy/backup-now.sh`.
- Когда была последняя копия и сколько места занято — в системе: «Настройки › Состояние
  сервера» (8.5 п. 4).

## Восстановление

```bash
./deploy/restore.sh /mnt/backup/planuchet/daily/2026-10-16_020000
```

Скрипт переспросит, остановит систему, заменит базу и файлы содержимым копии и запустит её
снова. Раз в квартал восстановление проверяется на отдельном сервере (8.3 п. 4): поставить
систему там же `install.sh`, затем `restore.sh` с копией боевого сервера.

## Производительность

Приложение работает несколькими процессами (`APP_WORKERS` в `deploy/.env`, по умолчанию 4 —
по числу ядер сервера): долгий отчёт или выгрузка не задерживают остальных. На сервере с
двумя ядрами поставьте 2, с восемью — можно 6–8; после правки — `install.sh`.

## Тестовые здания и стенд объёмов

- «Поликлиника» (ТЗ 7.2) — три этажа по придуманной планировке:
  `cd deploy && docker compose exec app python -m app sample polyclinic`.
- **Стенд объёмов 8.1** — для итоговой приёмки быстродействия (10.3), **только на отдельной
  установке**, не на рабочей: 20 зданий, около 10 000 помещений, 200 000 предметов (на
  одном этаже — 2 000), 50 000 единиц, 5 000 позиций остатков, 20 000 документов за год, 100
  учётных записей. `docker compose exec app python -m app sample volume` — около 10 минут.
  Замеры 8.2 на нём — `e2e/tests/volume.spec.ts` (`E2E_VOLUME=1`, README в `e2e/`).

## Если что-то не так

- Состояние: `cd deploy && docker compose ps`; журнал работы:
  `docker compose logs --tail 200 app worker`. Ошибка, которую видел пользователь, содержит
  код — найдите его в журнале работы: `docker compose logs app | grep <код>`.
- Забыт пароль, а сбросить его некому (единственный администратор):
  `cd deploy && docker compose exec app python -m app reset-password admin` — печатает
  временный пароль; сброс записывается в журнал.
- Остановить систему: `cd deploy && docker compose stop`; запустить: `docker compose up -d`.
