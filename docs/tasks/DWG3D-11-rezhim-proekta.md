# DWG3D-11: Проекты: режим проекта и итог применения

## Цель

После смены этажа редактор выходит из режима проекта, и правки незаметно идут в настоящую
расстановку (а перенос связанного предмета в другое помещение проводит «Перемещение» в учёте).
Нужно, чтобы из режима проекта нельзя было выйти незаметно (ТЗ 5.3.6 п. 2, 6.5.2), «Открыть на
плане» вело туда, где проект правят, а итог применения проекта был виден (5.3.6 п. 7, 6.1 п. 5).
Находки ревью 21.10.2026: R-042 (З), R-043 (Н), R-007 (З). Подзадача DWG3D-1.

      ждём CI.
- [x] Блок Б6 ручного прогона (`docs/review/MANUAL-RUN.md`) проходит (кроме PDF на Windows).

## Решения и находки

<!-- ГГГГ-ММ-ДД — что решили и почему; что пробовали и отвергли. Архитектурное → ADR. -->

- 2026-10-28 — расхождение с задачей Plane: R-007 уже «исправлена» в !2 (DWG3D-2): итог в
  `ApplyDialog` сбрасывается только при открытии окна, тест `web/src/projects/ApplyDialog.test.tsx`.
  В этой задаче — только проверка.
- 2026-10-28 — R-043 «всегда 1-й этаж» точнее: `ProjectPage.tsx:103` уже берёт нижний этаж из
  `floor_ids` (этажи с изменениями, по `position`). Первый этаж открывается у проекта без
  изменений — как в Б6: «Новый проект» → сразу «Открыть на плане».
- 2026-10-28 — найдено по коду: переходы, теряющие проект, кроме выбора этажа:
  `EditorPage` (адрес без этажа → первый этаж без `?project=`), «+ этаж» (`FloorDialog.onDone`),
  проект не загрузился → обычный режим. Осознанный выход — «Как есть» в выборе проекта, меню
  слева, поиск — проект не сохраняет, и это нормально: полоса и рамка пропадают по действию
  человека.
- 2026-10-28 — 3D в режиме проекта: другие этажи (`View3D.tsx:50`) читаются из расстановки
  (`/api/floors/…/items`), а не из проекта — в виде «здание до этажа» изменения проекта на других
  этажах не видны. Из проекта это не выводит; решение — ниже.
- 2026-10-28 — решили с Yury Mikhailov:
  - R-043: проект без изменений открывается на последнем открытом в редакторе этаже здания
    (в браузере), иначе на первом надземном. Отвергли меню этажей у «Открыть на плане» — лишний
    щелчок при каждом открытии; «оставить первый этаж» — R-042 это смягчает, но Б6 начинается
    с поиска этажа.
  - «+ этаж» в режиме проекта скрыт, как «Строительство» и «Сохранить план»: проект меняет только
    расстановку, этаж добавился бы в настоящее здание.
  - 3D другие этажи в режиме проекта — чиним здесь (R-053): та же тема, правка небольшая.
  - ADR не нужен: публичный API и схема не меняются, выбор — в поведении интерфейса.
- 2026-10-28 — R-043, уточнение к решению: если изменения есть на нескольких этажах и последний
  открытый — среди них, открывается он, а не нижний (вернулся к проекту — туда, где правил).
  Нижний этаж с изменениями — когда последний открытый без изменений. Проверяет третья часть
  теста R-043; если не нужно — убрать одно условие и эту часть.
- 2026-10-28 — шаг 1: четыре новых теста в `stage8.spec.ts` до исправления падают там, где
  дефект: R-042 — полосы проекта нет после смены этажа; R-043 — открылся 1-й этаж вместо 2-го;
  R-054 — `/plan/<здание>?project=…` → первый этаж без `?project=`; R-053 — запроса
  `/api/projects/<id>/floors/<1 этаж>` нет за 10 с. С9 локально падает на «PDF для
  руководства» (WeasyPrint без GTK на Windows) — как в DWG3D-6; в CI на Linux идёт целиком.
- 2026-10-28 — шаги 2–5: `stage8` — 4 новых зелёные, С9 падает только на PDF (Windows);
  повторно на старом интерфейсе (`git stash` правок `web/src`) новые 4 падают на тех же строках.
  В тестах был промах: `\?` в шаблонной строке — это `?`, в RegExp «необязательный символ»;
  исправлено на `\\?` до этой проверки. vitest — 75 из 75, `typecheck`, `lint` чистые.
- 2026-10-28 — 3D: ключ кэша других этажей — свой (`["items", этаж, "3d", проект]`), не как у
  редактора этажа: тот не обновляет кэш после правок, и только что правленный этаж 30 с
  показывался бы в 3D без них.
- 2026-10-28 — шаг 8, проверки как в CI локально: `ruff` чисто; `pytest` зелёный (тесты PDF на
  Windows пропущены); `typecheck`, `lint`, vitest 75 из 75, `vite build` — зелёные.
- 2026-10-28 — Б6 на стенде (`app_e2e` + `sample polyclinic`, встроенный браузер Claude, окно
  1280 × 800): шкаф в 216 поставлен в расстановку через API (в образце на 2 этаже предметов нет,
  в прогоне его ставили в Б3); дальше — мышью. 216 открыт на 2 этаже → «Проекты» → «Новый
  проект» «Процедурный 216» → «Открыть на плане» ведёт на 2 этаж; шкаф убран (красный
  пунктир), холодильник поставлен; в расстановке по-прежнему 1 предмет; смена на 3 этаж —
  полоса и рамка на месте; «Изменения и сравнение» — добавлен 1, убран 1; смета — 64 000 ₽;
  «Применить» → «Проект применён, перенесено изменений: 2», окно не сменяется вопросом.
  «PDF для руководства» не проверен — WeasyPrint на Windows.
- 2026-10-28 — наблюдение, к задаче не относится: если на этаже приблизить план и сменить этаж,
