# DWG3D-5: Инвентаризация: зависший запрос не держит очередь отметок

## Цель

На телефоне запрос с отметкой может повиснуть: соединение полуоткрыто или Wi-Fi слабый. Тогда
очередь отметок стоит без всякого сообщения, пока браузер сам не оборвёт запрос, а «Провести»
всё это время недоступно. Повторять отправку просто по тайм-ауту опасно: старый запрос может
дойти до сервера позже нового, перезаписать пересчёт старым числом или снова отметить вещь, с
которой отметку уже сняли. Задача закрывает находку ревью 21.10.2026 (родительская задача
DWG3D-1, `docs/review/FINDINGS.md`): R-049 (Н) — у отправки из очереди нет тайм-аута.

Решение согласовано в Plane: устройство нумерует свои отметки (UUID устройства в браузере и
номер по порядку), сервер хранит последний принятый номер пары «ведомость + устройство» и
пропускает запрос с номером не больше него; отправка обрывается через 15 с → «Нет связи» →
отметка отправляется заново. Меняются схема данных и API — ADR-0006.

## Критерии готовности

- [ ] Зависший запрос не держит очередь: через 15 с на экране «Нет связи», отметка досылается.
- [ ] Старый запрос, дошедший до сервера позже нового, не меняет ни отметку, ни пересчёт. Это
      касается и пары «отметить» → «снять отметку».
- [ ] Сценарий R-049 покрыт тестом, который до исправления падал.
- [ ] CI зелёный.
- [ ] В FINDINGS у R-049 стоит статус со ссылкой на MR.
- [ ] Если поменялось поведение, обновлены справка и `docs/`.

## Решения и находки

<!-- ГГГГ-ММ-ДД — что решили и почему; что пробовали и отвергли. Архитектурное → ADR. -->

- 2026-10-26 — предложение для ADR-0006 подтвердил Yury Mikhailov; записано в ADR-0006
  (статус «предложено» до merge):
  - устройство и номер — в заголовках `X-Count-Device` и `X-Count-Seq` у всех четырёх
    запросов: у «снять отметку» (`DELETE …/marks/{unit_id}`) нет тела;
  - без заголовков сервер принимает запрос, как раньше (API и тесты без устройства). Отметкам,
    которые остались в очереди от прежней версии, клиент даёт номера при чтении очереди;
  - пропущенный запрос — это успех (2xx), а не ошибка, иначе очередь выбросит отметку с
    сообщением. Скан отвечает `result: "skipped"`: без звука и без «найдена», ведомость
    просто обновляется;
  - номер даётся при постановке в очередь, а не при отправке: повтор после тайм-аута, 5xx или
    входа идёт с тем же номером. Счётчик один на устройство, он растёт и внутри каждой
    ведомости;
  - UUID — через `crypto.getRandomValues`: `crypto.randomUUID` есть только на HTTPS и
    localhost, а телефон в разработке ходит по `http://` на адрес компьютера в сети.
- 2026-10-26 — находка вне задачи: две вкладки одной ведомости досылают одну очередь
  (`busy` — на вкладку). Обе шлют первую отметку, и обе снимают первую из очереди, так что
  вторая может уйти не отправленной. С номерами повтор безвреден, а снимать отметку из
  очереди можно по номеру, а не по позиции, — это мелочь в шаге 5.
