# DWG3D-4: Инвентаризация: остатки с моделью и отметки с телефона

## Цель

Инвентаризация (С18) не проводится, если у остатков есть модели, а в образце они есть почти у
всех. Отметки с телефона теряются при перезапуске приложения или истёкшем сеансе. Задача
закрывает две находки ревью 21.10.2026 (родительская задача DWG3D-1,
`docs/review/FINDINGS.md`):

- R-021 (К) — инвентаризация не проводится при недостаче остатка, у которого есть модель;
- R-030 (Н) — офлайн-очередь выбрасывает отметки при 502 и 401.

## Критерии готовности

- [ ] С18 с пересчётом остатков проходит на образце `docs/samples/имущество-пример.xlsx`.
- [ ] Ни одна отметка не теряется при сбоях связи, сервера и сеанса.
- [ ] Сценарий каждой находки (R-021, R-030) покрыт тестом, который до исправления падал
      (из DWG3D-1).
- [ ] CI зелёный.
- [ ] В FINDINGS у R-021 и R-030 стоит статус со ссылкой на MR или с причиной.
- [ ] Если поведение изменилось, обновлены справка (`web/src/help/content.ts` → `docs/ADMIN.md`)
      и `docs/`.

## Решения и находки

<!-- ГГГГ-ММ-ДД — что решили и почему; что пробовали и отвергли. Архитектурное → ADR. -->

- 2026-10-26 — план утвердил Yury Mikhailov. R-021 — пересчёт по позиции «место + тип +
  модель» (ADR-0005). Распределять недостачу по моделям при пересчёте по типу не стали:
  неясно, на какую модель записать излишек, и в ведомости осталась бы одна строка на тип, а
  учёт ведётся по моделям. Пересчёт остатков отправляется через очередь отметок. «Провести»
  недоступно, пока очередь этого устройства не пуста. Что делать с пересчётом в черновиках
  при миграции, решается в ADR-0005: предложено проставить модель, если она однозначна,
  иначе удалить пересчёт этой строки.
- 2026-10-26 — перенос пересчёта при миграции утвердил Yury Mikhailov: модель однозначна —
  проставить, иначе удалить пересчёт этой строки. «Однозначна» — у типа в этом месте одна
  позиция с ненулевым остатком, с моделью или без. Позиций нет — пересчёт остаётся без модели,
  как и вёл себя раньше: при проведении это излишек. Проведённые и отменённые ведомости
  миграция не трогает. См. ADR-0005.
- 2026-10-26 — `count_stock`: ключ — суррогатный `id`, уникальность «документ + место + тип +
  модель» с `NULLS NOT DISTINCT` (PostgreSQL 16 на стендах и в CI). В первичный ключ модель не
  войдёт: столбец может быть пустым. Модель-заглушка вместо пустого значения сломала бы
  внешний ключ на `catalog.model`. Строки остатков в ведомости — по названию «тип + модель».
  Модель другого типа в `PUT stock` — 400.
- 2026-10-26 — правило очереди (R-030), заложено в тесты:
  - нет связи — ждать связи;
  - 5xx, 408, 429 и 409 `stale` — ждать сервера: повтор при следующей досылке, раз в 4 с;
  - 401 и 403 — ждать входа: очередь стоит, после входа `?next=` возвращает на ведомость, и
    очередь досылается;
  - остальные 4xx — отказ по самой отметке (единица списана, места нет в ведомости, ведомость
    проведена): выбросить и показать причину.

  403 отнесён к «ждать входа», а не к отказу: права могли отобрать у этой учётной записи, а
  отметки не теряются. 500 повторяется, как велит предложение в FINDINGS («5xx — повторять»).
  Цена — отметка, на которой сервер падает всегда, держит очередь за собой. Это видно на
  экране: «сервер не принимает, ждёт N».
- 2026-10-26 — очередь вынесена из `CountPage.tsx` в `queue.ts`, как `ApplyDialog` в ADR-0002:
  модуль проверяется без страницы. Источник правды — `localStorage`, состояние страницы — его
  отражение (`changed`). Защита от двойной досылки — набор ключей в модуле вместо `useRef`.
- 2026-10-26 — разбор кода (строки — по a5cec26):
  - R-021: `counts.py:108` `_stock_in` складывает остаток по (место, тип), все модели вместе;
    `CountStock` — ключ (документ, место, тип), модели нет; `post_count:439-450` пишет строки
    «недостача»/«излишек» без `model_id`. Проведение берёт остаток позиции с
    `model_id IS NULL` (`documents.py:430` `_position`), а у остатка с моделью его нет →
    «… — 0, нужно 1», не проводится вся ведомость. Излишек ложится отдельной позицией без модели.
  - В образце количеством с моделью учитываются перчатки, бахилы, бумага (склад 106),
    светильники (К1, К2, К3), стулья посетителя (201, 202); без модели — вешалки (103),
    стеллажи (106), молотки (203).
  - R-030: `CountPage.tsx:131-153` ждёт связи только при `code === "offline"` (исключение
    `fetch`, `lib/api.ts:33`). Любой ответ с ошибкой (502 Caddy при перезапуске, 503, 401)
    удаляет отметку из очереди. При 401 очередь за секунды уходит целиком, потому что каждая
    следующая отметка тоже получает 401.
  - Ответ 409 бывает двух видов. `stale` (`core/errors.py:62`) — гонка, «обновите и
    повторите», после R-022 так отвечают и на нарушение уникальности; такую отметку надо
    повторить. `conflict` «Инвентаризация уже проведена» — повтор бесполезен.
  - Пересчёт остатков (`StockRow`, `PUT /stock`) идёт мимо очереди: `void onSave(v)`, ошибка
    нигде не показывается, при обрыве связи число теряется.
  - После 401 `App.tsx:69` уводит на `/login?next=…`, после входа `Login.tsx:48` возвращает
    на ведомость. Очередь лежит в `localStorage` по ключу ведомости и после входа досылается
    сама, если её не выбрасывать.
