# DWG3D-2: CI и тесты

## Цель

CI ни разу не проходил (ТЗ 8.7 п. 2), то есть не защищает от регрессий, а ACCEPTANCE (этап 0)
утверждает обратное. На docker-раннере (пайплайн #1329, коммит 65fe750) задание `server` падает
на 7 тестах PDF (R-005), `e2e` ни разу не выполнялся. Часть тестов нестабильна (R-008, R-034),
не работает на Windows, где идёт разработка (R-006), или пропускает нарушения (R-010). Нужен
зелёный пайплайн, которому можно верить. Родительская задача — DWG3D-1 «Исправления по ревью
21.10.2026»; находки — `docs/review/FINDINGS.md`.

      с причиной.

## Решения и находки

- 2026-10-23 — пайплайн #1329 (`main`, 65fe750): `server` failed (7 ошибок PDF — ровно R-005,
  2 пропуска чертежей), `e2e` skipped, `web` и `agent-files` success. Задание `server` идёт ~12 мин.
- 2026-10-23 — на этой машине (Windows) WeasyPrint не загружается: `cannot load library
  'libgobject-2.0-0'` — тесты PDF без GTK здесь не пройдут.
- 2026-10-23 — `e2e` на чистой базе: 4 из 46 падают — `a11y` ×2 и `stage4` (R-008), `stage8:71`
  (R-007, дефект интерфейса «Применить проект», не в списке задачи — взят решением ниже).
- 2026-10-23 — `web/src` импортирует модули без расширений (`./plan`), поэтому нынешний скрипт
  `"test": "node --test 'src/**/*.test.ts'"` модули редактора не загрузит — для R-003 нужен
  vitest или аналог.
- 2026-10-23 — до 65fe750 задания без тегов брал shell-раннер «Сборщик»
  (`srv-ubuntu-gitlab-runner`): `uv: command not found`, `npm: command not found` — до тестов
  не доходило ни разу. Docker-раннер — `srv-ubuntu-docker-runner` на том же хосте. В GitLab
  проекта включён реестр образов (на случай варианта 3 из ADR-0001).
- 2026-10-23 — CI на docker-раннере, Pango в задании `server` ставит `before_script` теми же
  пакетами, что `deploy/Dockerfile`; свой образ для CI не собираем. См. ADR-0001.
- 2026-10-23 — MR-пайплайн #1341 (1db6e03) упал на тех же 7 тестах PDF: правка с Pango тогда
  ещё не была запушена. Запушена в bac154c.
- 2026-10-23 — R-008, `a11y`: проверяемый план — всегда своё здание (два кабинета, дверь, стол),
  а не «Поликлиника» или первое попавшееся. Так результат не зависит от базы. На базе
  разработки план «Поликлиники» больше не проверяется — это осознанная цена.
- 2026-10-23 — R-007: итог в `ApplyDialog` сбрасывается эффектом только на `open`, а не на
  новые данные предпросмотра.
- 2026-10-23 — первый зелёный пайплайн проекта — MR #1343 (121c1d4): `server` 11 мин,
  `e2e` 5,5 мин (41 passed, 7 skipped), `web` 2 мин, `agent-files`. До правки R-008 (#1342)
  `e2e` в CI — ровно 3 failed: `a11y` ×2, `stage4:171`.
- 2026-10-23 — тест на R-007 — компонентный: vitest + jsdom + Testing Library
  (`web/src/projects/ApplyDialog.test.tsx`), `ApplyDialog` вынесен в свой файл, чтобы тест не
  тянул редактор и 3D. Второй ответ предпросмотра тест отпускает сам внутри `act`: без правки
  падает 5 из 5, с правкой проходит 10 из 10. e2e так не умеет: после правки новый предпросмотр
  ничего не меняет на экране, ждать нечего. jsdom 29, а не 30: 30 требует Node ≥ 24.15, здесь
  24.14. См. ADR-0002.
- 2026-10-23 — R-006: кроме теста архитектуры, без кодировки читал `index.json` базового
  каталога сам `catalog/module.py` — на Windows падал не только тест, но и загрузка 3D-моделей
  каталога. Исправлено и чтение `last.json` в `system/api.py`.
- 2026-10-23 — тесты PDF помечены фикстурой `pdf` (не маркером: не нужен `import pytest` в
  7 файлах, и видно в сигнатуре). Без WeasyPrint — пропуск, при `CI` — `pytest.fail`.
- 2026-10-23 — R-034: тишина до `ping` вынесена в `app.main.PING_AFTER`; тест ставит 0,01 с,
  и `ping` гарантированно приходит первым — так падение воспроизводится на любой машине.
- 2026-10-23 — R-010: проверка вынесена в `_module_violations(root)`, тест подкладывает 5 обходов
  из ревью во временный каталог. До правки правил ловился 1 из 5 (`zz_import`), как в ревью.
- 2026-10-23 — исходный прогон на Windows (HEAD 121c1d4): 13 failed из 102, 9,7 мин — 3
  `UnicodeDecodeError`, 2 `WinError 32`, 7 PDF, 1 события (`ping` вместо `user.create`).
- 2026-10-23 — **настоящая причина R-034 на Windows** — не «медленная машина». Подключение к
  `localhost:55432` идёт ~130 с: `localhost` сначала `::1`, а база проброшена только на
  `127.0.0.1` (`-p 127.0.0.1:55432:5432`), и попытка по IPv6 висит до таймаута TCP; к
  `127.0.0.1` — 0,02 с. Поток событий делал `LISTEN` через 2 минуты, изменение из теста терялось.
  Мой первый вариант теста (пропускать `ping` без предела) из-за этого завис на 40 мин.
  Исправлено: адрес по умолчанию — `127.0.0.1:55432` (`tests/conftest.py`, `app/core/config.py`,
  AGENTS.md, README.md, `.claude/launch.json` — `server`, `worker`, `volume`, `volume-worker`);
  у `events.Hub` признак `listening`, тест ждёт его до изменения и пропускает `ping` не дольше
  5 с. Тесты событий и архитектуры на Windows — 9 с вместо минут.
- 2026-10-23 — версии uv в CI были разные: `e2e` ставил последнюю (сегодня 0.13.5), а образ
  `ghcr.io/astral-sh/uv:python3.12-bookworm-slim` у `server` — это 0.9.30: версионные образы uv
  на bookworm выходили до 0.9.30 (04.02.2026), дальше только trixie, а плавающий тег застыл
  (дайджест `e5b65587…` = `0.9.30-python3.12-bookworm-slim`). Закрепили 0.9.30 — то, что уже
  работало, и Debian 12, как в `deploy/Dockerfile`. Переезд на trixie — вместе с deploy
  (R-038, часть deploy — не в этой задаче). См. ADR-0001.
- 2026-10-23 — решили с Yury Mikhailov:
  - R-007 чиним в этой задаче: без него `e2e` на чистой базе не зелёный, правка небольшая,
    а `stage8` уже воспроизводит дефект.
  - R-003 — заводим vitest (стек уже на Vite), тесты на чистые функции редактора, ADR.
  - Тесты PDF на Windows без GTK пропускаются с причиной; при заданной `CI` отсутствие
