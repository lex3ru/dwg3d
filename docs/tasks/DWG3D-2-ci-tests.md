# DWG3D-2: CI и тесты

## Цель

CI ни разу не проходил (ТЗ 8.7 п. 2), то есть не защищает от регрессий, а ACCEPTANCE (этап 0)
утверждает обратное. На docker-раннере (пайплайн #1329, коммит 65fe750) задание `server` падает
на 7 тестах PDF (R-005), `e2e` ни разу не выполнялся. Часть тестов нестабильна (R-008, R-034),
не работает на Windows, где идёт разработка (R-006), или пропускает нарушения (R-010). Нужен
зелёный пайплайн, которому можно верить. Родительская задача — DWG3D-1 «Исправления по ревью
21.10.2026»; находки — `docs/review/FINDINGS.md`.

- [ ] Пайплайн зелёный на `main` и в MR во всех заданиях, включая `e2e` на чистой базе.
- [ ] Тесты сервера проходят на Windows.
- [ ] Перевод CI на раннер docker (уже в 65fe750) записан ADR.
- [ ] По R-003 решение принято.
- [ ] Сценарий каждой находки покрыт тестом, который до исправления падал (из DWG3D-1).
- [ ] В FINDINGS у R-003, R-005, R-006, R-007, R-008, R-010, R-034, R-038 (часть CI) — статус
      с причиной.

## Решения и находки

<!-- ГГГГ-ММ-ДД — что решили и почему; что пробовали и отвергли. Архитектурное → ADR. -->

- 2026-10-23 — пайплайн #1329 (`main`, 65fe750): `server` failed (7 ошибок PDF — ровно R-005,
  2 пропуска чертежей), `e2e` skipped, `web` и `agent-files` success. Задание `server` идёт ~12 мин.
- 2026-10-23 — на этой машине (Windows) WeasyPrint не загружается: `cannot load library
  'libgobject-2.0-0'` — тесты PDF без GTK здесь не пройдут.
- 2026-10-23 — `e2e` на чистой базе: 4 из 46 падают — `a11y` ×2 и `stage4` (R-008), `stage8:71`
  (R-007, дефект интерфейса «Применить проект», не в списке задачи — взят решением ниже).
- 2026-10-23 — `web/src` импортирует модули без расширений (`./plan`), поэтому нынешний скрипт
  `"test": "node --test 'src/**/*.test.ts'"` модули редактора не загрузит — для R-003 нужен
  vitest или аналог.
- 2026-10-23 — до 65fe750 задания без тегов брал shell-раннер «Сборщик»
  (`srv-ubuntu-gitlab-runner`): `uv: command not found`, `npm: command not found` — до тестов
  не доходило ни разу. Docker-раннер — `srv-ubuntu-docker-runner` на том же хосте. В GitLab
  проекта включён реестр образов (на случай варианта 3 из ADR-0001).
- 2026-10-23 — CI на docker-раннере, Pango в задании `server` ставит `before_script` теми же
  пакетами, что `deploy/Dockerfile`; свой образ для CI не собираем. См. ADR-0001.
- 2026-10-23 — MR-пайплайн #1341 (1db6e03) упал на тех же 7 тестах PDF: правка с Pango тогда
  ещё не была запушена. Запушена в bac154c.
- 2026-10-23 — R-008, `a11y`: проверяемый план — всегда своё здание (два кабинета, дверь, стол),
  а не «Поликлиника» или первое попавшееся. Так результат не зависит от базы. На базе
  разработки план «Поликлиники» больше не проверяется — это осознанная цена.
- 2026-10-23 — R-007: итог в `ApplyDialog` сбрасывается эффектом только на `open`, а не на
  новые данные предпросмотра.
- 2026-10-23 — первый зелёный пайплайн проекта — MR #1343 (121c1d4): `server` 11 мин,
  `e2e` 5,5 мин (41 passed, 7 skipped), `web` 2 мин, `agent-files`. До правки R-008 (#1342)
  `e2e` в CI — ровно 3 failed: `a11y` ×2, `stage4:171`.
- 2026-10-23 — решили с Yury Mikhailov:
  - R-007 чиним в этой задаче: без него `e2e` на чистой базе не зелёный, правка небольшая,
    а `stage8` уже воспроизводит дефект.
  - R-003 — заводим vitest (стек уже на Vite), тесты на чистые функции редактора, ADR.
  - Тесты PDF на Windows без GTK пропускаются с причиной; при заданной `CI` отсутствие
    WeasyPrint — ошибка, чтобы пропуск в пайплайне не прятал дефект.
