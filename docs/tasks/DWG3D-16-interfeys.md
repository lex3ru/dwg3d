# DWG3D-16: Интерфейс: 3D, режим только просмотра, перехват ошибок, QR-метки

## Цель

Мелкие дефекты интерфейса из ревью 21.10.2026 (подзадача DWG3D-1): мерцание стен в 3D
(R-029); «просмотру» и гостю показаны указания по правке и серые поля — нарушение ТЗ 2.3,
6.1 п. 3 (R-031); любой сбой отрисовки, прежде всего 3D, даёт белый экран (R-032); адрес в
QR-метках зависит от того, откуда их печатали, а ссылка должна быть постоянной — ТЗ 5.4.7
(R-016); раскрытый отчёт растягивает соседний блок (R-046).

## Критерии готовности

- [ ] Блоки Б1 и Б7 ручного прогона (`docs/review/MANUAL-RUN.md`) проходят без замечаний.
- [ ] Сбой 3D (нет WebGL, ошибка в сцене) не роняет приложение: на месте 3D — сообщение,
      план и остальной редактор работают.
- [ ] QR-метки (единиц, складов, ячеек, мест) ведут на постоянный адрес системы, а не на
      адрес браузера печатающего.
- [ ] Сценарий каждой находки покрыт тестом, который до исправления падал (R-033).
- [ ] В FINDINGS у R-016, R-029, R-031, R-032, R-046 — статус со ссылкой на MR.
- [ ] Справка (`web/src/help/content.ts` → `docs/ADMIN.md`) и `docs/` обновлены, где
      поменялось поведение; решение по адресу меток — ADR (меняется API печати меток).
- [ ] CI зелёный.

## План

- [ ] 1. R-046 — отчёты: e2e в `stage7.spec.ts` (высота соседнего блока не меняется при
      раскрытии отчёта) падает; `items-start` у сетки `ReportsPage.tsx`.
- [ ] 2. R-032 — граница ошибок разделов: компонент в `web/src/ui/`, в `Shell` и
      `GuestShell` вокруг содержимого раздела (сброс при переходе); сообщение и
      «Перезагрузить». Модульный тест: исключение в разделе — сообщение, меню на месте.
- [ ] 3. R-032 — граница 3D: вокруг `Canvas` в `View3D.tsx` «3D недоступно…», план работает;
      потеря контекста WebGL — то же сообщение и «Попробовать снова». e2e: без WebGL
      (`getContext` → `null`) 3D показывает сообщение, план правится.
- [ ] 4. R-031 — «просмотр» и гость: поля редактора (`NumberField`, `TextField`, `Segmented`,
      выбор в `Properties.tsx`, `calc.tsx`, `link.tsx`) в режиме только чтения — текстом,
      без подсказок «что писать»; `FloorSummary` — без указаний по правке. Те же поля в
      каталоге у не-администратора (`TypeCard`, `CatalogPage`, `PurposesPage`). Тесты:
      модульные (нет `input`, нет «Перетащите…») и e2e для «просмотра».
- [ ] 5. R-016 — адрес меток: настройка «Адрес системы для QR-меток» в «Настройках»; пустая —
      `APP_PUBLIC_URL` (из `PUBLIC_URL` установки, `compose.yml`), без него (разработка) —
      адрес запроса. Печать меток единиц/складов/ячеек и меток мест берёт её, поле `origin`
      из `POST /api/inventory/labels.pdf` убрано. В интерфейсе — предупреждение, если
      печатают не с этого адреса. Тест: адрес в метке не зависит от адреса запроса. ADR-0016.
- [ ] 6. R-029 — 3D: порядок перекрытия совпадающих граней (`polygonOffset`: колонны поверх
      несущих, несущие поверх перегородок) и `near` по расстоянию до цели в обзоре
      (в прогулке — как сейчас). Модульный тест на материалы и `near`; проверка в браузере
      на «Поликлинике» — снимки до и после.
- [ ] 7. Справка и `docs/`: `content.ts` → `npm run admin-guide`, `docs/INSTALL.md`
      (`PUBLIC_URL` — и адрес меток), статусы в `docs/review/FINDINGS.md`.
- [ ] 8. Проверки как в CI (ruff, pytest, web, e2e `stage4`/`stage5`/`stage7`, a11y);
      ручной прогон Б1 и Б7 на стенде.

## Решения и находки

<!-- ГГГГ-ММ-ДД — что решили и почему; что пробовали и отвергли. Архитектурное → ADR. -->

- 2026-10-29 — причина мерцания (R-029) уточнена по коду: в узле все стены продлеваются на
  половину наибольшей толщины (`joinExtensions`), и стены разных материалов перекрываются:
  верх перегородки совпадает с верхом несущей, торец — с её дальней гранью. Колонны в стенах
  совпадают с ними верхом. Совпадающие грани одного материала одинаковы по цвету и не видны.
  Вдобавок `near: 0.05` при `far: 2000`: на 150 м точность глубины ≈ 3 см.
- 2026-10-29 — R-016: `PUBLIC_URL` уже есть в `deploy/.env` (его пишет `install.sh`, Caddy
  перенаправляет на него с `http://`), но приложению не передаётся. Метки мест
  (`reports/routes.py`) берут `request.base_url` — за Caddy это тоже адрес, по которому
  открыли систему.
- 2026-10-29 — R-031: те же поля (`NumberField`, `TextField`, `Segmented` из
  `editor/Properties.tsx`) — серые и в каталоге у не-администратора (`ro = role !== "admin"`).

- 2026-10-29 — выбрано с пользователем: R-016 — поле в «Настройках» (по умолчанию —
  `PUBLIC_URL` установки), а не только `PUBLIC_URL`: адрес меняют без перезапуска; R-029 —
  порядок граней и `near`, а не объединение контуров (без новой зависимости, мало кода);
  R-031 — редактор и каталог: поля у них общие, ТЗ 2.3 нарушено в обоих.
