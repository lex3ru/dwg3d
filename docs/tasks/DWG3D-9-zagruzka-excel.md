# DWG3D-9: Загрузка имущества из Excel и строки документа

## Цель

Начальное наполнение учёта из Excel (С10, ТЗ 5.4.9, 7.3 п. 1) не пройти: после проверки файла
окно пишет «Есть что исправить (2)», но строки ошибок сжаты до нулевой высоты. Вещи легко
загрузить не в то помещение: совпадение по номеру считается «точным», даже если название
другое, а метки «точно / похоже / не найдено» не различаются. В строке документа выпадающий
список «Наименование» обрезается карточкой. Подзадача DWG3D-1 (ревью 21.10.2026), находки
R-047 (З), R-002 (З), R-045 (Н), R-044 (Н).

## Решения и находки

<!-- ГГГГ-ММ-ДД — что решили и почему; что пробовали и отвергли. Архитектурное → ADR. -->

- 2026-10-27 — согласовано с Yury Mikhailov: (1) подтверждение блокирует загрузку — пока
  помещение не подтверждено («Верно» или другое место), это ошибка строки; подтверждения
  требует только совпадение по номеру с другим названием, остальные «похоже» — выделяются;
  (2) ADR не нужен: `/api/inventory/import` — для окна загрузки, не внешний API (в `docs/`
  не описан), в ответе добавляется поле; (3) отдельного «образца с ошибками» не заводим —
  ошибки дают повторная загрузка `имущество-пример.xlsx` (номера заняты).
- 2026-10-27 — порог «названия совпадают» для помещения, найденного по номеру, — 0,9, а не
  0,75, как у поиска по названию. На образце `similarity` даёт 0,8 для «Кабинет невролога» ↔
  «Кабинет кардиолога» и 0,7 для «Кабинет офтальмолога» ↔ «Кабинет невролога»: при 0,75
  первое осталось бы «точно». При 0,9 «Процедурный» ↔ «Процедурный кабинет» (e2e С10) — по-прежнему
  «точно», а на образце подтверждения требуют 13 из 15 помещений с номером (кроме 201, 202):
  кабинеты в образце условные (ТЗ 4.6 п. 1).
- 2026-10-27 — `UnitPicker` в документе стоит под карточкой строк, а не в ней, поэтому
  карточка его не обрезает; переводим на тот же портал, чтобы списки вели себя одинаково.
- 2026-10-27 — в ответе проверки не новое поле с названием помещения плана, а признак
  `confirm`: помещение плана уже есть в `place_title`. Ошибки сопоставления получили `name` /
  `room` — окно показывает их у своей строки таблицы, общим списком — только ошибки строк файла.
- 2026-10-27 — `toBeVisible` пропускает элемент, обрезанный прокручиваемым предком (так С10 и
  прошёл с R-047). В новых e2e видимость — `toBeInViewport`: он считает долю по
  IntersectionObserver, с учётом обрезки. До исправления: строка ошибки — 0, список типов — 0,47.
- 2026-10-27 — R-044: Radix Popover, а не свой портал: позиционирование и переворот вверх у
  края экрана, закрытие по Esc и щелчку мимо, слои Radix-окон — Esc закрывает список, а не окно
  «Вещь без метки», щелчок в списке не считается щелчком мимо окна (проверено в браузере).
  Content рисуется как `ul role="listbox"` (`asChild`): иначе у него роль `dialog`, и
  `getByRole("dialog")` в тестах видел бы лишнее окно.
- 2026-10-27 — так было и до задачи, не трогали: после выбора типа список снова открывается,
  только если уйти из поля и вернуться — фокус остаётся в поле, `onFocus` не срабатывает.
- 2026-10-27 — Б4 на дев-стенде скриптом Playwright: образец в «Поликлинику» при занятых
  номерах — «Есть что исправить (56)», 44 ошибки «номер уже занят» видны списком, у 12 помещений
  «похоже — подтвердите» (на дев-базе план поликлиники правлен прошлыми задачами, поэтому не 13).
  Подсказка «на плане — …» дублировала ошибку строки — теперь только когда ошибки нет.
- 2026-10-27 — полный pytest нашёл ещё два теста, которые грузили образец с пустым
  сопоставлением (`test_counts::test_c18_*`, `test_reliability::test_crash_*`): после R-002 образец
  без подтверждения не загружается. Общий помощник `confirmed_rooms` в `test_inventory.py`.
- 2026-10-27 — пайплайн #1424: красное только e2e `perf.spec.ts` «8.2: расчёты» — зона обзора
  622 мс при пороге 200 (в #1423 и #1421 — 83 и 99 мс, освещённость та же). Модуль расчётов в
  задаче не менялся — флак, тот же, что в DWG3D-8; после перезапуска — 86 мс, #1424 зелёный.
