# DWG3D-14: Безопасность: стоимость для «просмотра», зависимости, укрепление

## Цель

«Просмотр» может вычислить стоимость по порядку сортировки реестра, а ТЗ 2.2 запрещает
показывать её «в любом виде». В зависимостях сервера есть известные уязвимости. Плюс набор
советов по укреплению: CSP, `/api/docs` без входа, файлы по UUID без проверки владельца,
`localStorage` после выхода, `Origin` у `/api/ws`, формулы в выгрузках Excel. Подзадача
DWG3D-1 (ревью 21.10.2026); находки R-015 (Н), R-004 (Н), R-018 (С) — в
`docs/review/FINDINGS.md`.

      выгрузки при `sort=±price` не зависит от цены, при равных ключах — не от номера.
- [x] Известных уязвимостей в зависимостях нет (R-004): `pip-audit` по `uv.lock`,
      `npm audit` в `web/` и `e2e/` — 0.
- [x] По каждому пункту R-018 решение принято: все шесть сделаны (FINDINGS, ADR-0014).
- [x] Сценарий каждой находки покрыт тестом, который до исправления падал (R-033): сервер —
      `test_r015_*`, `test_r018_*` (6 тестов, коммит 502daf2 до исправлений); интерфейс —
      привязка черновика и очереди (проверено откатом `userKey`).
- [x] CI зелёный; в FINDINGS у находок статус со ссылкой на MR; справка и `docs/` обновлены,

## Решения и находки

<!-- ГГГГ-ММ-ДД — что решили и почему; что пробовали и отвергли. Архитектурное → ADR. -->

- 2026-10-28 — `pip-audit` на `main` (302921d): 41 уязвимость в двух пакетах — Pillow 12.3.0
  (39, исправлены в 13.0.0; в ревью их было 8) и brotli 1.2.0 (2, исправлены в 1.2.1; brotli
  приходит через `fonttools[woff]` от WeasyPrint и ezdxf). `npm audit` в `web/` и `e2e/` — 0.
  `uv lock --dry-run` поднимает оба пакета без других изменений.
- 2026-10-28 — Кроме сортировки реестра, других путей к стоимости для «просмотра» не нашёл:
  параметр `sort` есть только у реестра и его выгрузки (`inventory/routes.py`), фильтров по
  цене нет, остальные ответы закрыты `sees_cost` и проверены
  `test_security.py::test_viewer_gets_no_cost_numbers_or_projects_anywhere`.
- 2026-10-28 — Решения по R-018 с Юрием Михайловым. (2) `/api/docs` и `/api/openapi.json` —
  только администратору, а не выключить: схема нужна при отладке и интеграции; у Swagger своя
  CSP, потому что он грузит скрипты с CDN. (4) `localStorage` — только привязать к
  пользователю, при выходе не чистить: неотправленные отметки и черновик плана не должны
  теряться из-за выхода, а чужой пользователь их и так не увидит. (1) CSP задаёт приложение,
  а не Caddy: e2e в CI идёт на `uvicorn` мимо Caddy (`.gitlab-ci.yml`, задание `e2e`), и
  только так тесты увидят нарушения CSP.
- 2026-10-28 — CSP: `object-src blob:`, а не `'none'`. Метки печатаются как PDF из `blob:`
  в новой вкладке; такая вкладка наследует политику, и PDF в ней — «объект». `default-src`
  без явного `object-src` закрыл бы его так же. `'wasm-unsafe-eval'` нужен декодеру meshopt
  у `useGLTF`: drei создаёт его при загрузке любой модели. Draco-декодер drei берёт с gstatic —
  под CSP он не загрузится; в закрытой сети не загружался и раньше. Записано в ADR-0014 и
  `docs/architecture.md`, кандидат на отдельную задачу (раздавать декодер со своего сервера).
- 2026-10-28 — CSP только на `index.html`, а не на всех ответах: файлы `/api/files/…` (PDF)
  открываются в браузере напрямую, политика им ни к чему. Скрипт темы вынесен в
  `web/public/theme.js` — встроенный скрипт CSP запретила бы.
- 2026-10-28 — Excel: опасен только `=` — openpyxl делает формулой только его, а `+ - @` в
  ячейке-строке Excel не вычисляет (это риск CSV, а CSV-выгрузок нет). Строка с `=` пишется
  ячейкой с типом «строка» (`core/report.text_cell`/`text_row`), без приписки `'`: текст в
  выгрузке остаётся тем же. Ячейки создаются только для таких строк — реестр до 50 000 строк.
- 2026-10-28 — Файлы: проверка доступа — подписки модулей-владельцев (`on_file_access`,
  бывший `on_guest_file`), а не владелец в записи файла: без миграции, файл бывает у
  нескольких владельцев (модель — у нескольких типов). Фото единицы проверяется и по
  `photo_file_id`: из пакета переноса оно бывает без строки `unit_file`. ADR-0014.
- 2026-10-28 — `localStorage`: данные прежней версии (ключ без пользователя) достаются первому
  вошедшему — иначе после обновления пропали бы неотправленные отметки.
- 2026-10-28 — Конфигурации `.claude/launch.json` на этой машине не запускаются:
  `preview_start` не находит `sh`. e2e на сборке с CSP гонял сервером и worker из Git Bash, как
  в CI (`APP_STATIC_DIR=../web/dist`, порт 8012).
