# DWG3D-13: Журнал и живые обновления

## Цель

Не каждое изменение данных пишется в журнал (ТЗ 9.2 п. 3): черновики документов учёта, правки
содержимого проекта, перенос имущества при объединении помещений. Ленты журнала по зданию,
этажу и документу открыть нельзя (5.7.3). «Просмотру» не приходят изменения учёта
(6.1 п. 8), а заблокированный пользователь или завершённый сеанс продолжает получать события
до разрыва соединения. Подзадача DWG3D-1 (ревью 21.10.2026); находки R-011, R-012, R-041 (Н) —
в `docs/review/FINDINGS.md`.

## Решения и находки

<!-- ГГГГ-ММ-ДД — что решили и почему; что пробовали и отвергли. Архитектурное → ADR. -->

- 2026-10-28 — при разборе: `create_document` тоже не пишет журнал (в R-011 не указан —
  скрипт ревью смотрел строку `update_document`). У карточки единицы нет перехода в журнал —
  вкладка «История» показывает только правки карточки; автор переноса при объединении
  помещений будет виден в журнале единицы.
- 2026-10-28 — журнал не знает, к какому зданию относится помещение или единица (модуль
  нижнего уровня), поэтому ссылки `building:`/`floor:` добавляет тот, кто пишет запись, — как
  уже делают `building` и `planning`. Варианты и выбор — ADR-0013 (там же страж журнала и
  перепроверка сеанса в сокете).
- 2026-10-28 — старые записи (до исправления) в ленты здания и этажа не попадают: дописать им
  ссылки — значит править журнал, а он не правится (5.7.3). Согласовано с Yury Mikhailov.
- 2026-10-28 — черновики: `create_document`/`update_document` пишут журнал (правка
  человеком), а `new_draft`/`edit_draft` — нет: ими пользуются загрузка из Excel, перенос
  здания, отмена, инвентаризация и «составить и провести» (`inventory.api.post_document`),
  где изменение данных — проведение, и его запись уже есть. Иначе одно действие давало бы три
  записи (создан, изменён, проведён).
- 2026-10-28 — страж журнала (`tests/conftest.py`): события SQLAlchemy на сессиях запросов
  (подмена `get_session` в тестовом приложении) собирают изменённые таблицы; транзакция
  зафиксирована без `journal.entry` — тест падает. Точка сохранения (`begin_nested` в
  проведении) не проверяется — запись будет после неё. Служебные таблицы — `NOT_DATA` с
  причиной: сеанс, очередь задач, файл до привязки, отметки обхода (хранят автора и время,
  итог — в проведении; так решило и ревью). Сырой SQL страж не видит.
- 2026-10-28 — страж нашёл ещё запуск перевода чертежа (`start_convert` меняет статус и ставит
  задачу без записи): теперь `drawing.convert_start` — кто и когда запустил, даже если перевод
  не завершится.
- 2026-10-28 — сокет: перепроверка по `RECHECK_AFTER` (25 с) и сразу по событию, где сущность
  — сам пользователь (`user:<id>`: блокировка, смена зданий, сброс пароля). Не по каждой записи
  со ссылкой `user:<id>` — она есть у всех действий самого пользователя, лишний запрос к базе.
  Выход (`logout`) журнал не пишет — сокет других вкладок закроется по таймеру.
- 2026-10-28 — «просмотру» не уходят события `project.*`: проектов он не видит (2.2), а
  записи проектов несут ссылку на здание. Данных в событии нет, но и сам факт правки — лишнее.
- 2026-10-28 — в тестах второй `TestClient` на том же приложении запускает второй слушатель
  канала (`hub.start` в lifespan) — события приходят дважды. В работе процесс один; тест
  ждёт нужное событие, а не «следующее».
- 2026-10-28 — ленты здания и этажа — фильтрами журнала (`?building=&floor=`), одной сущности
  — `?ref=&about=` (`about` — подпись над лентой, её даёт переход). Этаж — в «Зданиях» (значок
  у этажа) и в редакторе («Журнал этажа», когда ничего не выбрано).

**Как проверить.**
- `cd server && uv run ruff check app migrations tests && uv run pytest` — страж работает на
  всех тестах; новые: `test_journal.py` (`r011`, `r041`), `test_events.py` (`r012`).
- `cd web && npm run typecheck && npm run lint && npm test && npx vite build`.
- `cd e2e && npx playwright test tests/stage9.spec.ts -g "С22"`.
- Руками: черновик документа → «Журнал» (создан, изменён с «было / стало»); удалить черновик —
  запись остаётся в ленте здания; «Здания» → «Журнал» и значок у этажа; в редакторе — «Журнал
  этажа». «Просмотр» с открытой страницей «Имущество» — проведите документ в его здании,
  список обновится сам; заблокируйте его — страница уйдёт на вход.

**За рамками.**
- Записи до DWG3D-13 в ленты здания и этажа не попадают (журнал не правится).
- Сервер разработки не стартует через `.claude/launch.json` из инструмента предпросмотра: нет
  `sh` в PATH; сервер и интерфейс запускались во вкладках терминала.
- В тестах два `TestClient` на одном приложении запускают два слушателя канала — события
  приходят дважды (в работе процесс один).
