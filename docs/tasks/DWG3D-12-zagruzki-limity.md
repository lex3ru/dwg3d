# DWG3D-12: Загрузки и фоновые задачи: лимиты, тяжёлые и испорченные файлы

## Цель

Сейчас без входа можно заставить сервер записать на диск файл любого размера. Лимиты из ТЗ 7.3
п. 4 соблюдаются не для всех видов файлов. Испорченный или тяжёлый файл даёт 500 или надолго
останавливает очередь фоновых задач, отменить задачу нельзя. Подзадача DWG3D-1 (ревью
21.10.2026); находки R-014 (З), R-040, R-025, R-026, R-017 (Н), R-013 (С) — в
`docs/review/FINDINGS.md`.

## Критерии готовности

- [ ] Большая загрузка без входа отклоняется, не попав на диск (R-014).
- [ ] Лимиты для всех шести видов файлов — по ТЗ 7.3 п. 4 и меняются в настройках (R-040).
- [ ] Тяжёлый чертёж не останавливает очередь, а задачу можно отменить (R-026).
- [ ] Испорченный GLB — понятная ошибка, не 500; «размножающееся» дерево узлов отказывается сразу (R-025).
- [ ] `dwg2dxf` — без секретов в окружении и с лимитом памяти и процессора (R-017).
- [ ] Перезапуск обработчика возвращает в очередь только задачи «молчащих» обработчиков;
      подписки модулей не удваиваются (R-013).
- [ ] Сценарий каждой находки покрыт тестом, который до исправления падал (R-033).
- [ ] CI зелёный; в FINDINGS у находок статус со ссылкой на MR; справка и `docs/` обновлены.

Вне рамок: отдельный контейнер для `dwg2dxf` без сети (R-017, «при желании»), прочие пункты
R-018 (укрепление) — другие подзадачи DWG3D-1.

## План

<!-- Проверяемые шаги. Отмечайте выполненное, добавляйте найденное по ходу. -->

- [ ] 1. ADR: обработчик фоновых задач — задача в дочернем процессе (таймаут и отмена —
      остановкой процесса, транзакция откатывается сама), две полосы («чертежи» и
      «остальное»), пульс задач; новые поля `core.job` и `POST /api/system/tasks/{id}/cancel`.
      Лимиты загрузок: проверка входа и размера до приёма тела, лимит в Caddy.
- [ ] 2. Тесты, которые падают (R-033), по всем находкам: загрузка без входа читает тело
      (счётчик прочитанного из потока); чертёж 101 МБ, подложка 51 МБ, Excel 11 МБ принимаются;
      нет настроек для четырёх видов; GLB из `artifacts/stage4-glb-fuzz.txt` — 500 и зависание
      (с таймаутом теста); задача без конца держит очередь, отменить нельзя; после неудачного
      перевода чертёж остаётся «переводится»; `dwg2dxf` получает окружение с паролем базы;
      `_requeue_interrupted` забирает задачу живого обработчика; второй `create_app()` удваивает
      подписки.
- [ ] 3. R-040: настройки шести лимитов с умолчаниями ТЗ (ключи `photo_max_mb` и
      `document_max_mb` — прежние, значения сохраняются); чертёж, подложка, Excel (каталог и
      имущество), 3D — проверка до разбора; верхняя граница настроек — общий предел
      `files.MAX_SIZE`; седьмая настройка — «Пакет переноса — до, МБ» (2048, вне 7.3);
      экран «Настройки».
- [ ] 4. R-014: до чтения тела загрузки — `Content-Length` не больше общего предела (иначе 413),
      вход администратора (иначе 401/403); тело без `Content-Length` считается при приёме и
      обрывается на пределе. Caddy: `request_body max_size` по общему пределу, пакету переноса —
      свой.
- [ ] 5. R-025: ошибки разбора GLB → «GLB повреждён»; узел, встреченный дважды (цикл или
      общий потомок — по glTF 2.0 у узла один родитель), — отказ; предел глубины.
- [ ] 6. R-026 и R-013: задача в дочернем процессе, таймаут по виду задачи, отмена (очередь —
      сразу, выполняется — остановкой процесса), статус `cancelled`; полосы; пульс и имя
      обработчика у задачи, возврат в очередь только «молчащих»; при неудаче и отмене модуль
      возвращает чертёж из «переводится»/«разбирается»; идемпотентные `on_*`.
- [ ] 7. R-017: `dwg2dxf` — пустое окружение (только `PATH`, `LD_LIBRARY_PATH`), в Linux
      `setrlimit` памяти и процессора; таймаут — не больше таймаута задачи.
- [ ] 8. Интерфейс: «Отменить» у хода задачи (чертежи, перенос, отчёты), «отменено» в
      уведомлениях; проверка в браузере на стенде.
- [ ] 9. FINDINGS (статусы, новая находка о «переводится»), справка `content.ts` →
      `npm run admin-guide`, `docs/INSTALL.md` (лимит Caddy), `docs/architecture.md`
      (обработчик); проверки как в CI.

## Решения и находки

<!-- ГГГГ-ММ-ДД — что решили и почему; что пробовали и отвергли. Архитектурное → ADR. -->

- 2026-10-28 — согласовано с Yury Mikhailov: (1) R-026 — задача в дочернем процессе,
  остановка процесса по таймауту и отмене, две полосы (не проверки флага в коде задачи: долгий
  вызов внутри shapely или LibreDWG так не прервать); (2) пакет переноса — своя настройка,
  2 ГБ по умолчанию; (3) лимит числа примитивов не вводим (причина ниже).
- 2026-10-28 — FastAPI разбирает multipart (`UploadFile`) до зависимостей входа и прав: тело
  целиком ложится во временный файл, только потом 401. Поэтому вход проверяется в прослойке до
  чтения тела, а не в маршрутах.
- 2026-10-28 — пакет переноса здания (`/api/transfer/check`) везёт все файлы здания — фото,
  чертежи, документы — и бывает больше любого лимита 7.3. Один `request_body max_size 110MB` в
  Caddy (предложение R-014) сломал бы перенос: у пакета свой лимит.
- 2026-10-28 — вероятная новая находка: `convert_drawing` падает (например, R-023 `needs_place`)
  → транзакция задачи откатывается целиком, и `drawing.status` остаётся `converting`, записанным
  ещё при постановке в очередь. Чертёж навсегда «переводится», повторный перевод отказывает
  («ещё обрабатывается»). Тест R-023 этого не проверяет. Отмена и таймаут дадут то же — нужен
  обработчик неудачи задачи.
- 2026-10-28 — лимит числа примитивов чертежа (предложение R-026) не вводим: 50 000 случайных
  пересекающихся линий — патология, а у реального плана этажа примитивов бывает столько же и
  больше; чертежей заказчика для калибровки нет. Тяжёлый чертёж останавливает таймаут или
  отмена, очередь не ждёт его благодаря полосам.
