# catalog

Каталог: типы мебели и оборудования, наборы свойств, из которых собираются схемы
типов, 3D-модели. Читает каталог любой вошедший, меняет — администратор системы.

## Схема типа

Схема — свойства наборов типа по порядку, затем собственные свойства типа
(`GET /types/{id}/schema`). У свойства:

| Поле | Значения | Смысл |
|---|---|---|
| `key` | латиницей | по ключу значение хранится; не меняется после создания |
| `kind` | `text`, `number`, `date`, `bool`, `choice`, `person` | вид значения |
| `stored` | `type` / `asset` | значение одно на тип (хранится здесь, в `values`) или у каждого объекта |
| `editable_by` | `system` / `admin` / `responsible` | кто правит: каталог, администратор здания, ответственный |

Ключ в схеме типа встречается один раз, из какого бы набора ни пришёл: тип или набор,
нарушающие это, не сохраняются (`409 key_conflict`). Изменение набора увеличивает
`schema_version` всех типов с этим набором и публикует их список; изменение самого
типа увеличивает версию схемы, только если изменилась схема или признаки «контейнер»,
«переносной».

Признаки типа: `container` — в объект можно вкладывать другие; `portable` — объект
может перемещать ответственный. Тип не удаляется, а уходит в архив: его нет в выборе,
но он открывается по ссылке, и объекты этого типа остаются.

## Запросы

`/api/catalog/v1` — `contracts/openapi/catalog.v1.json`.

| Запрос | Что делает |
|---|---|
| `GET /categories`, `POST` / `PATCH` / `DELETE /categories…` | разделы; с типами внутри раздел не удалить |
| `GET /property-sets`, `GET` / `PATCH` / `DELETE /property-sets/{id}`, `POST /property-sets` | наборы свойств; используемый набор не удалить |
| `GET /types?category_id=&q=&active=`, `GET /types/{id}`, `POST /types/batch-get` | типы (с развёрнутой схемой) |
| `GET /types/{id}/schema` | схема свойств типа |
| `POST /types`, `PATCH /types/{id}` | создать, изменить |
| `POST /types/{id}/archive` / `/restore` | в архив / вернуть |
| `PUT` / `DELETE /types/{id}/model`, `GET /types/{id}/model.glb` | 3D-модель (GLB) |

Модель крупнее 20 МБ или с размерами, отличающимися от габаритов типа больше чем вдвое,
принимается с предупреждением (`model.warnings`): чаще всего это модель в миллиметрах.

## События

| Публикует | Когда |
|---|---|
| `catalog.type.created` / `.changed` / `.archived` / `.restored` | тип; в событии — версия схемы и изменилась ли она |
| `catalog.property_set.changed` | набор; в событии — типы, схема которых изменилась |

Событий не получает.

## С чего каталог начинается

Первая миграция записывает согласованное в ТЗ (приложение А): разделы «Медицинская
техника» и «Мебель», наборы «Учёт», «Медицинское изделие», «Мебель» и пять типов —
аппарат КТ, гастроскоп, рабочий стол, кушетка, кресло посетителя (`app/seed.py`).
Дальше каталог ведут администраторы: повторный запуск ничего не перезаписывает.

Инвентарный и серийный номер, состояние, ответственный и примечание — поля любого
объекта (сервис `assets`), а не свойства схемы.

## Чего пока нет

Запрет удалять свойство и менять его вид, когда у объектов уже есть значения, появится
вместе с сервисом `assets` (этап 4): каталогу пока не у кого спросить.
