# assets

Объекты: мебель и оборудование как предметы на плане — со свойствами по схеме типа,
состоянием, ответственным, файлами и историей.

## Объект

- **Тип** из каталога; схему свойств сервис держит у себя (`type_schemas`) и обновляет по
  событиям каталога, поэтому работает и когда каталог недоступен.
- **Место** — точка этажа (помещение определяется по точке запросом к `buildings`; точка
  вне помещений отклоняется) либо **контейнер**: объект внутри другого не имеет своих
  координат и переезжает вместе с ним. Вложенность — один уровень.
- **Инвентарный номер** уникален и не используется повторно, даже после списания.
- **Состояние**: в работе, неисправен, в ремонте, на складе, списан.
- **QR-код** — 10 знаков без похожих букв и цифр; не меняется при перемещении.
- **История** — каждое изменение с автором и значениями «было → стало». Изменение можно
  откатить, пока эти поля с тех пор не менялись.

## Кто что может

| Действие | Кому |
|---|---|
| видеть объект, его файлы и историю | у кого есть право на объект или на помещение, этаж, здание над ним |
| свойства с `editable_by: responsible`, примечание, состояние, файлы | ответственному (за объект или помещение) и администратору здания |
| перемещать переносной объект — в помещение, которое видит | ответственному и администратору |
| остальные свойства, номера, ответственный, постановка, перемещение стационарных, списание, откат | администратору здания |

Отказ называет причину («Свойство „Год выпуска“ меняет администратор здания»). Объект,
на который нет прав, не существует (404) — в том числе по QR-коду. Назначение
ответственного даёт ему право на объект: сервис `access` выдаёт его по событию.

## Запросы

`/api/assets/v1` — `contracts/openapi/assets.v1.json`.

| Запрос | Что делает |
|---|---|
| `GET /assets` | список видимого; фильтры: здание, этаж, помещение, тип, раздел, состояние, ответственный, контейнер, «требует размещения / заполнения», поиск, значения свойств (`prop.<ключ>`, `.gte`, `.lte`) |
| `GET /assets/{id}` | объект со схемой, вложенными объектами и тем, что с ним может спрашивающий (`can`) |
| `POST /assets`, `POST /assets/batch` | поставить один; несколько одинаковых с номерами подряд — всё или ничего |
| `POST /assets/import?building_id=` | из Excel (Тип, Инвентарный номер, Серийный номер, Этаж, X, Y, Примечание): всё или ничего, ошибки по строкам |
| `PATCH /assets/{id}` | номера, примечание, свойства — каждое по своим правам |
| `POST /assets/{id}/state`, `/responsible`, `/move` | состояние (в том числе списание), ответственный, перемещение |
| `GET /assets/{id}/history`, `POST …/history/{entry}/revert` | история, откат |
| `GET` / `POST /assets/{id}/files`, `GET` / `DELETE /files/{id}` | фотографии и документы |
| `GET /qr/{code}` | чей это QR-код; нет права — `404`, как и у несуществующего |
| `GET /assets/{id}/label?size=` | QR-метка объекта в PDF: ссылка `TWIN_PUBLIC_URL/q/<код>`, номер, тип; сторона наклейки 20–100 мм |
| `POST /labels` | лист меток на A4: выбранные объекты или всё помещение, этаж, здание — администратору здания |
| `GET /usage?type_id=&prop=` | есть ли значения свойства — для каталога |

Изменения несут `version`; при расхождении — `409` с текущим состоянием объекта.

## События

Публикует `assets.asset.created`, `.changed`, `.moved`, `.state_changed`,
`.responsible_changed`, `.retired`, `.file_added`, `.file_removed` — с идентификаторами
здания, этажа, помещения и объекта в конверте.

| Получает | Реакция |
|---|---|
| `catalog.type.*`, `catalog.property_set.changed` | взять схему заново; объекты, не проходящие её, — «требует заполнения» |
| `buildings.room.retired` | объекты помещения — «требует размещения» (остаются привязаны к нему) |
| `buildings.revision.published` | сдвинуть точки выровненных иначе этажей; каждому объекту найти помещение по точке у `buildings` — в другом помещении переносится, вне помещений — «требует размещения» |
| `buildings.room.split` / `.merged` | объекты разделённого — по своим точкам; объекты объединённых — в наследника |
| `people.person.left` | снять выбывшего с ответственных |

Списание контейнера оставляет вложенные объекты в помещении с отметкой «требует размещения».

## При отказе соседей

Без каталога объекты известных типов читаются и правятся. Без `buildings` нельзя только
ставить и перемещать — с объяснением. Без `access` чтение идёт до 5 минут по последним
известным правам, изменения отклоняются.

## Запуск и тесты

```bash
docker compose -f deploy/docker-compose.yml up -d db db-init nats s3
cd services/assets
uv run python -m twin_chassis.migrate && uv run uvicorn app.main:build --factory --port 8000
uv run ruff check . && uv run pytest
```

В тестах `access`, `buildings` и `catalog` заменены заглушками.
