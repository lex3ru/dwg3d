# people

Люди: справочник организации и связь человека с учётной записью.

Справочник один на организацию. Ведут его администраторы зданий (любой, кто
администрирует хотя бы одно) и администратор системы — у кого есть такое право,
сервис спрашивает у `access`. Имя и должность человека по идентификатору открыты
любому вошедшему: они нужны, чтобы показать ответственного и автора изменения.
Кто кого видит по помещениям — появится с привязкой людей к помещениям (этап 6).

## Учётная запись и человек

- При первом входе (`GET /me`) учётная запись связывается с человеком по почте — если
  с этой почтой в справочнике ровно один действующий человек без учётной записи.
- Если таких несколько, связь не создаётся (`reason: ambiguous`): администратор
  связывает вручную (`PUT /people/{id}/link`).
- Нет в справочнике — `reason: unknown`; выбыл — `reason: left`. Во всех трёх случаях
  прав у учётной записи нет.
- «Выбыл» (`POST /people/{id}/leave`) отзывает все права человека (событие `left`).

## Запросы

`/api/people/v1` — `contracts/openapi/people.v1.json`.

| Запрос | Что делает |
|---|---|
| `GET /me` | запись спрашивающего; при первом входе связывает по почте |
| `GET /people?q=&department=`, `GET /people/{id}` | справочник |
| `POST /people`, `PATCH /people/{id}` | добавить, изменить (с `version`) |
| `POST /people/{id}/leave` | человек выбыл |
| `PUT` / `DELETE /people/{id}/link` | связать с учётной записью вручную / разорвать связь |
| `POST /people/import` | Excel: столбцы ФИО, Должность, Подразделение, Почта, Телефон |
| `POST /people/batch-get` | имя и должность по идентификаторам — любому вошедшему |

Импорт: человек узнаётся по почте, без неё — по ФИО и подразделению, поэтому повторная
загрузка того же файла никого не создаёт. Строки с ошибками перечисляются в ответе
и пропускаются.

## События

| Публикует | Когда |
|---|---|
| `people.person.created` / `.changed` | добавлен / изменён (в событии — какие поля, без значений) |
| `people.person.linked` / `.unlinked` | связь с учётной записью |
| `people.person.left` | человек выбыл |

Событий не получает. Персональных данных в событиях нет — только идентификаторы.

## Запуск и тесты

```bash
docker compose -f deploy/docker-compose.yml up -d db db-init nats
cd services/people
uv run python -m twin_chassis.migrate && uv run uvicorn app.main:build --factory --port 8000
uv run ruff check . && uv run pytest
```

В тестах `access` заменён заглушкой.
