# gateway

Шлюз — единая точка входа системы. Своих данных не хранит, кроме сессий входа.

| Адрес | Что делает |
|---|---|
| `GET /auth/login?next=` | начинает вход: переадресация в Keycloak (код авторизации с PKCE) |
| `GET /auth/callback` | завершает вход: создаёт сессию, ставит cookie `twin_session` |
| `POST /auth/logout` | завершает сессию; в ответе — адрес выхода из Keycloak |
| `GET /api/me` | кто вошёл |
| `/api/<сервис>/v1/…` | пропускает запрос в сервис, подставляя токен пользователя вместо cookie |
| `GET /api/stream` | события в браузер (Server-Sent Events) |
| `GET /api/system/status` | состояние сервисов — администратору системы |

Полное описание — `contracts/openapi/gateway.v1.json` (при запущенном шлюзе: `/api/docs`).

## Как устроено

- **Сессия.** В браузере — случайное значение в cookie (HttpOnly, SameSite=Lax), в базе —
  его хэш и токены Keycloak, зашифрованные ключом из `TWIN_SECRET`. Токен доступа
  обновляется здесь за 30 секунд до истечения; если Keycloak отказал — сессия закрывается.
- **Пропуск запросов.** Сервис получает `Authorization: Bearer <токен пользователя>` и
  сквозной `X-Request-ID`; cookie дальше не уходит. Сервисы проверяют токен сами.
  Запрос со своим токеном (программа, а не браузер) проходит без сессии.
- **Защита от чужих страниц.** Изменяющий запрос с cookie принимается, только если
  `Origin` совпадает с адресом системы.
- **События.** Шлюз слушает шину и раздаёт события подключённым браузерам. До этапа 2
  (сервис «Доступ») администратор системы видит все события, остальные — только свои
  (`app/stream.py: visible`).
- **Отказы.** Сервис недоступен — `503 service_unavailable` с его именем; Keycloak
  недоступен — `503 auth_unavailable`.

## Настройки

Общие — как у любого сервиса (`libs/chassis`), плюс:

| Переменная | По умолчанию | Что задаёт |
|---|---|---|
| `TWIN_PUBLIC_URL` | `http://localhost:8090` | адрес системы для пользователей; на него возвращает вход |
| `TWIN_OIDC_CLIENT_SECRET` | `dev-client-secret` | секрет клиента `twin` в Keycloak |
| `TWIN_SECRET` | `dev-secret-change-me` | подпись состояния входа и шифрование токенов |
| `TWIN_SERVICES` | — | куда пропускать запросы: `ping=http://ping:8000,…` |
| `TWIN_SESSION_DAYS` | `14` | срок жизни сессии без обращений |

## События

Не публикует. Слушает все (`twin.>`) без гарантий доставки — только чтобы показать
в браузере; обработчиков с изменением данных у шлюза нет.

## Запуск и тесты

```bash
docker compose -f deploy/docker-compose.yml up -d db db-init nats keycloak
cd services/gateway
uv run python -m twin_chassis.migrate
uv run uvicorn app.main:build --factory --port 8000
uv run ruff check . && uv run pytest
```

В тестах Keycloak и сервис заменены заглушками за HTTP-клиентом шлюза; нужны только
PostgreSQL и NATS стека разработки.
