# Сервис подсчёта проходов (ADR-0028)

Отдельный процесс, один экземпляр на установку. Основное приложение хранит настройки,
историю и права; сервис читает RTSP независимо от просмотра. Подтверждение события
отстаёт примерно на 8 секунд. Одна линия на камеру, точка со стороны входа; разметка
нормирована к исходному кадру. Прямоугольные зоны и слияние камер пока не подключены.

## Запуск на Linux рядом с приложением

1. Создать случайный служебный токен (не меньше 32 байт), сохранить в файле с правами
   0600 вне Git. В процессе приложения установить APP_ANALYTICS_TOKEN в то же значение.
2. Запустить обновлённое приложение: штатный `serve` применяет миграцию 0019.
3. Подготовить каталог с весами `yolo11n.pt` (в локальном примере они есть).
4. Задать COUNTING_MODEL_DIR (абсолютный путь к каталогу весов), COUNTING_TOKEN_FILE
   (абсолютный путь к файлу токена), при необходимости COUNTING_APP_URL.
5. `docker compose -f services/counting/compose.yml up -d --build` из корня проекта.
6. В окне камеры → «Аналитика»: разметить порог, указать сторону входа, включить и
   сохранить. «Обработка идёт» означает свежий heartbeat и обработанные кадры.

Контейнер использует сеть хоста Linux, чтобы обращаться к приложению на 127.0.0.1:8010.
Собственный порт сервис не открывает. Для отдельного компьютера URL приложения должен
быть доступен по HTTPS либо через защищённую внутреннюю сеть. Пароли камер передаются
в служебной конфигурации, но не сохраняются в SQLite и не выводятся в лог.
Не запускайте несколько экземпляров на одних камерах: это приведёт к двойному учёту.

## Доставка и ограничения

SQLite в именованном томе хранит события до подтверждения приложения. Повторы с тем же
UUID не увеличивают счётчик. Недоставленные события переживают перезапуск контейнера.
Незавершённые треки при рестарте могут потеряться. Потеря диска с очередью — потеря
недоставленных событий; следите за свободным местом. История удаляется вместе с камерой.
Конфигурация опрашивается каждые 3 секунды; heartbeat — примерно каждые 20 секунд,
через 60 секунд без него интерфейс показывает отсутствие связи.

В core/ сохранена копия вычислительного ядра предоставленного примера video/door_counter
(2026-11-03). Исходная папка video — отдельный локальный репозиторий, не меняется
и не требуется для сборки образа.
Датасеты, веса, кэш, видеозаписи и виртуальное окружение в образ не входят.
Проверки: `video/.venv/bin/python -m pytest services/counting/test_worker.py
video/door_counter/tests/test_logic.py -q`. Веса и производительность на реальной камере
проверяются отдельно; цифры из README прототипа не являются гарантией точности.
