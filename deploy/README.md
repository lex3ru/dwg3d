# Развёртывание

Весь стек новой версии — `deploy/docker-compose.yml` (проект Compose `twin`).

| Сервис | Что делает |
|---|---|
| `web` | Caddy: собранный интерфейс и единая точка входа (`/api`, `/auth` → шлюз, `/kc` → Keycloak) |
| `gateway` | шлюз: сессии входа, пропуск запросов в сервисы, события в браузер |
| `import`, `import-worker` | чертежи: загрузка и файлы сборок; очередь сборок DWG → модель (`--scale import-worker=N`) |
| `buildings` | здания, этажи, помещения |
| `ping` | сервис-образец |
| `db` | PostgreSQL: один сервер, база и роль на каждый сервис |
| `db-init` | при каждом запуске создаёт недостающие базы и роли из `TWIN_DATABASES` |
| `nats` | шина событий (JetStream) |
| `keycloak` | вход; realm `twin` импортируется из `deploy/keycloak/` при первом запуске |
| `kc-init` | при каждом запуске создаёт в Keycloak учётные записи сервисов (`twin-svc-<имя>`) из `TWIN_SERVICE_CLIENTS` |
| `s3` | S3-совместимое хранилище файлов (RustFS) |

## Запуск

На своей машине:

```bash
cp deploy/.env.example deploy/.env
docker compose -f deploy/docker-compose.yml up -d --build
```

Откройте http://localhost:8090 — первый вход `admin` / `admin`, Keycloak попросит сменить пароль.

На сервере:

```bash
deploy/make-env.sh https://twin.example.com twin.example.com   # deploy/.env со случайными паролями
docker compose -f deploy/docker-compose.yml up -d --build
```

Второй аргумент — домен, для которого Caddy сам получит сертификат; без него — обычный HTTP
(за другим прокси с TLS). Пароль первого пользователя — `TWIN_ADMIN_PASSWORD` в `deploy/.env`.

Порты по умолчанию не пересекаются с текущей версией из `legacy/`:

| Что | Порт | Переменная |
|---|---|---|
| вход в систему | 8090 (HTTPS 8453) | `TWIN_HTTP_PORT`, `TWIN_HTTPS_PORT` |
| PostgreSQL (только с этой машины) | 5433 | `TWIN_DB_PORT` |
| NATS (только с этой машины) | 4223 | `TWIN_NATS_PORT` |
| Keycloak напрямую (только с этой машины) | 8181 | `TWIN_KEYCLOAK_PORT` |
| S3 (только с этой машины) | 9002 | `TWIN_S3_PORT` |

## Чертежи DWG

DXF читается напрямую, DWG — через конвертер. В образе `import` установлен LibreDWG;
ODA File Converter читает DWG надёжнее и нужен для сохранения DWG с правками. Чтобы
подключить его, смонтируйте исполняемый файл в контейнеры `import` и `import-worker`
(`docker-compose.override.yml`) и укажите путь внутри контейнера в `TWIN_ODA`.

## Обновление одного сервиса

```bash
docker compose -f deploy/docker-compose.yml up -d --build <сервис>
```

Остальные сервисы продолжают работать; миграции базы сервис применяет сам при запуске.
Запросы к нему во время перезапуска получают `503`, события дожидаются в шине.

## Новый сервис

```bash
tools/new-service <имя> "Название по-русски"
docker compose -f deploy/docker-compose.yml up -d --build <имя> db-init gateway
```

Команда создаёт `services/<имя>` из шаблона и вписывает сервис в Compose (сам сервис, его
база и пароль), в маршруты шлюза и в CI. В существующий `deploy/.env` пароль базы
(`TWIN_DB_PASSWORD_<ИМЯ>`) нужно добавить вручную.

## Резервные копии

```bash
deploy/backup.sh                    # в TWIN_BACKUP_DIR (по умолчанию deploy/backups/<дата-время>/)
```

Сохраняются все базы (сервисов и Keycloak) и хранилище файлов; стек при этом работает.
Хранятся последние `TWIN_BACKUP_KEEP` копий (по умолчанию 14). Для ежедневного запуска — cron:

```
30 2 * * *  /путь/к/репозиторию/deploy/backup.sh >> /var/log/twin-backup.log 2>&1
```

События в пути (NATS) в копию не входят: после восстановления расхождения между
сервисами устраняет их сверка (docs/DATA_MODEL.md, раздел 11).

## Восстановление

На том же сервере — базы и файлы **заменяются** содержимым копии:

```bash
deploy/restore.sh deploy/backups/20261005-151506
```

На чистом сервере:

1. Установить Docker, получить репозиторий.
2. Положить `deploy/.env` **с прежнего сервера** (в нём `TWIN_SECRET`, которым зашифрованы
   сессии, секрет клиента Keycloak и адрес системы) и каталог копии.
3. `deploy/restore.sh <каталог копии>` — поднимет базу, создаст роли, восстановит базы и
   файлы, запустит стек.
4. Войти администратором и открыть «Состояние системы»: все сервисы должны отвечать.

Адрес системы должен остаться прежним: он записан в настройках входа Keycloak. При смене
адреса поправьте `TWIN_PUBLIC_URL` и адреса клиента `twin` в консоли Keycloak (`/kc/admin/`).
