# pdf2dxf

Готовит DXF для CAD-систем из PDF с чертежом.

## Установка и запуск

```bash
uv sync
uv run pdf2dxf plan.pdf                      # -> plan.dxf рядом с PDF
uv run pdf2dxf plan.pdf -o out.dxf -s 1:100  # масштаб чертежа 1:100
uv run pdf2dxf plan.pdf -p all               # все страницы: plan_p1.dxf, plan_p2.dxf, ...
uv run pytest                                # тесты
```

## Окно (GUI)

```bash
uv run pdf2dxf-gui            # или: uv run pdf2dxf-gui plan.pdf
```

Слева настройки, справа вкладки «PDF» (предпросмотр страницы, определяется тип графики) и «Результат DXF»
(колесо — масштаб, мышь — сдвиг, двойной щелчок — вписать). Внизу журнал. Нужен `tkinter` (в Linux:
`sudo apt install python3-tk`, если в вашем Python его нет).

## Два режима

| Режим | Когда | Результат |
|---|---|---|
| `vector` | PDF из CAD/BIM (AutoCAD, nanoCAD, Revit, ArchiCAD…): линии лежат в файле как геометрия | точный: LINE, ARC, CIRCLE, LWPOLYLINE, SPLINE, HATCH, TEXT |
| `raster` | скан или картинка внутри PDF: в файле только пиксели | приблизительный: линии восстанавливаются трассировкой, кривые становятся ломаными |

`--mode auto` (по умолчанию) выбирает режим для каждой страницы сам: растр — если на странице почти нет
векторных путей, а картинка занимает больше половины листа.

## Импорт в цифровой двойник

Конвейер разбора (`services/import`) находит стены **по имени слоя** (`layers.walls`: `*WALL*`, `*Стен*`…),
а в большинстве PDF слоёв нет (так у «Поэтажные планы Бастион.pdf»: всё чёрное, только разная толщина).
Без этого импорт отвечает «Не найдено ни одного этажа: проверьте маппинг слоёв стен».

```bash
uv run pdf2dxf plan.pdf -s 1:200 --twin       # то же — галочка «Импорт в цифровой двойник» в окне (включена по умолчанию)
```

`--twin` = `--drop-frame --stroke-layer A-WALL --fill-layer Штриховка`:
все линии идут на слой `A-WALL`, рамка листа удаляется (иначе она станет «стеной» размером с лист),
заливки (в таких PDF это буквы, переведённые в кривые) — на слой `Штриховка`, который конвейер игнорирует.
Имена можно задать свои: `--stroke-layer`, `--fill-layer`.

**Масштаб обязателен**: в DXF мм, и конвейер читает их как реальные. Для плана Бастиона подходит `-s 1:200`
(площади небольших помещений совпали с подписями на плане). Если сомневаетесь — промерьте на плане
известный размер и подберите масштаб. Названия помещений конвейер не получит, пока подписи — кривые.

## Что переносится (vector)

- линии, дуги (кривые Безье, похожие на дугу, заменяются настоящими ARC; полный круг → CIRCLE), полилинии, прямоугольники;
- остальные кривые — SPLINE;
- цвет → слои (`C_RRGGBB`); если в PDF есть слои (OCG) — используются их имена;
- толщины линий и пунктир (создаются типы линий `PDF_DASH_n`);
- заливки → HATCH на слоях `F_RRGGBB` (белые и на весь лист пропускаются);
- текст → TEXT (слой `TEXT`), кириллица работает; поворот сохраняется. Текст, превращённый в кривые, приходит как геометрия.

## Масштаб и единицы

Единицы DXF — миллиметры. Без `-s` размеры равны размерам на бумаге. Если чертёж напечатан в масштабе 1:100,
укажите `-s 100` (или `-s 1:100`) — получите реальные размеры в модели. Проверьте результат любым замером
известного размера.

## Ограничения

- Растровый режим не распознаёт текст (OCR нет), окружности и дуги получаются ломаными, заливки — чёрные.
  Для сканов лучше сначала поднять качество (300 dpi и выше, ровный контраст).
- Касающиеся отрезки одного слоя и стиля склеиваются в полилинии, на Т- и Х-узлах склейка останавливается;
  одинаковые дубли отрезков удаляются.
- Текст, переведённый в кривые (так часто экспортируют PDF24/Ghostscript), приходит как заливки-глифы, а не TEXT: распознать его нельзя.
- Обрезка (clip) и прозрачность PDF не учитываются.
- Размерные линии/выноски приходят отдельными линиями и текстом, а не как DIMENSION.
