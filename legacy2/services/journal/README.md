# journal

Журнал — неизменяемая лента событий всех сервисов (docs/TZ.md, 4.7). Подписан на всю шину
(`twin.>`), хранит каждое событие как пришло: вид, время, автор, область (здание, этаж, помещение,
объект, человек — из конверта), данные. Сам ничего не публикует и ничего не меняет.

Событие хранится один раз: обработчик пишет его в одной транзакции с отметкой «обработано», повтор
доставки ничего не добавляет. Пока журнал остановлен, события ждут в JetStream и дочитываются после
запуска — без пропусков.

## Запросы

`/api/journal/v1` — `contracts/openapi/journal.v1.json`.

| Запрос | Что делает |
|---|---|
| `GET /events?building_id=&floor_id=&room_id=&asset_id=&person_id=&actor_id=&type=&from=&to=&limit=&cursor=` | лента, новые сверху; `type` — точно или по началу (`assets.`); страницы по `next` |
| `GET /events/{id}` | событие |

Кто что видит: событие видит тот, у кого есть право `view` на его область (объект → помещение → этаж →
здание — что указано в конверте); события о человеке — он сам; лента без выбора области —
администратор системы. Чужие события в ответ не попадают.

## Настройки

Общие — `twin_chassis.settings`; `TWIN_SERVICES` — адрес `access` (права спрашиваются с токеном
читателя); `TWIN_JOURNAL_KEEP_DAYS` — срок хранения (по умолчанию 1825 дней), более старые события
удаляются раз в сутки.

Отступление от `docs/DATA_MODEL.md`: таблица одна, без секций по месяцам — удаляются строки, а не секции.

```bash
cd services/journal
uv run python -m twin_chassis.migrate && uv run uvicorn app.main:build --factory --port 8000
uv run ruff check . && uv run pytest
```
