# Ввод в проект

Цель — за 10–15 минут дать человеку рабочую картину проекта и проверить, что окружение живое. Код не меняй.

## Шаги

1. Прочитай `AGENTS.md`, `docs/README.md`, `docs/architecture.md`, `docs/glossary.md`.
2. Прочитай индекс `docs/decisions/README.md` и последние 5 ADR по номеру.
3. Найди активные задачи: файлы `docs/tasks/*.md`, у которых в шапке `status` не `done`. Для каждой возьми `id`, `title`, `owner`, `status` и строку «Следующий шаг» из блока «Handoff».
4. Посмотри историю: `git log --oneline -20` и недавние ветки: `git branch -r --sort=-committerdate`, первые 10.
5. Если доступен `glab` — открытые MR: `glab mr list`.
6. Проверь окружение: выполни команды из раздела «Быстрый старт» в `AGENTS.md`. Долгие и опасные команды (миграции, деплой, удаление данных) не запускай — только перечисли. Проверь, что подключены git-хуки: `git config core.hooksPath` должен вернуть `.githooks`. Если нет — предложи выполнить `git config core.hooksPath .githooks`.
7. Выдай сводку, не длиннее экрана:
   - что делает система и для кого — 2–3 предложения;
   - карта модулей: каталог → ответственность;
   - как запустить и проверить; какие команды не сработали и почему;
   - ключевые решения — по строке на ADR;
   - активные задачи — таблица: ID, название, кто ведёт, статус, следующий шаг;
   - пробелы в документации: устаревшие команды, пустые разделы, противоречия с кодом.
8. Предложи правки в `AGENTS.md` и `docs/`. Вноси их только после согласия пользователя, отдельным коммитом `docs: ...`.

## Режим «проект без документации»

Если `AGENTS.md` нет или в нём остались заглушки `ЗАПОЛНИТЬ`:

1. Изучи репозиторий: манифесты зависимостей, точки входа, конфигурацию CI, скрипты, тесты.
2. Составь черновик `AGENTS.md` по структуре шаблона. Только проверяемые факты: команды, каталоги, правила из линтеров и CI. Не больше 150 строк.
3. Составь черновик `docs/architecture.md`: компоненты, внешние системы, хранилища, потоки данных.
4. Покажи черновики пользователю и попроси вычитать и сократить. Сгенерированные инструкции работают хуже написанных людьми, поэтому финальную версию правит человек.
