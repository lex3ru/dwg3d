# Завершить задачу

## Шаги

1. **Проверки.** Запусти все проверки из `AGENTS.md`: линтеры, типы, тесты. Если что-то красное — почини или остановись и сообщи пользователю.
2. **Критерии готовности.** Пройди по каждому критерию из файла задачи: выполнен ли и чем это подтверждается (тест, ручная проверка). Невыполненное обсуди с пользователем.
3. **Документация.** Обнови то, что изменилось: `docs/architecture.md`, `docs/glossary.md`, `README`. `AGENTS.md` меняй, только если поменялись команды, структура или правила для всех.
4. **Решения.** Для каждого архитектурного решения из «Решений и находок» должен быть ADR. Если нет — навык `adr`.
5. **Файл задачи.** В шапке `status: done` и сегодняшняя дата в `updated`. В «Журнал сессий» — итоговая запись. Блок «Handoff» замени итогом: что сделано, как проверить, что осталось за рамками задачи. Если ревью вернёт задачу, `pickup` снова поставит `in-progress`.
6. **Описание MR** — по шаблону `.gitlab/merge_request_templates/Default.md`. Если доступен `glab`: `glab mr update <branch> --description "<текст>"`, затем `glab mr update <branch> --ready`. Иначе отдай текст пользователю.
7. Если подключён Plane MCP — переведи задачу на ревью и оставь комментарий со ссылкой на MR.
8. Напомни пользователю: перед merge человек читает весь diff и должен уметь объяснить каждое изменение.
